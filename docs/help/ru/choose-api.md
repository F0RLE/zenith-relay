# Выбор API

> ChatGPT подключается напрямую к совместимому hosted API. В этом режиме Relay
> не создаёт личный пул и не ведёт собственный журнал запросов.

Выбирайте режим, если уже есть endpoint и API-ключ провайдера. Для маршрутизации
своих аккаунтов ChatGPT используйте **Этот компьютер** или **Мой сервер**.

## Что подготовить

- API-ключ провайдера для inference-запросов.
- Корень совместимого API, обычно с окончанием /v1.
- Модель, которую поддерживает провайдер.
- Поддержку **Responses API**, если нужна кнопка прямого **Подключить ChatGPT**.

Управляющий токен из режима **Мой сервер** не является inference API-ключом.

## Подключение API

1. В переключателе режима выберите **Выбор API**.
2. Откройте **Подключения → Источники** и нажмите **Добавить источник**.
3. Выберите известного провайдера или **Свой API**.
4. Введите название, корень API, ключ и протокол. Для прямого подключения
   профиля ChatGPT/Codex выберите **Responses API**.
5. Сохраните источник и дождитесь обнаружения моделей, если выбран режим
   **Автоматически**. В меню источника нажмите **Подключить ChatGPT**, если
   есть нативный маршрут Responses.
6. Подтвердите резервную копию профиля. После закрытия Relay запросы продолжит
   обслуживать провайдер.

Источник Chat Completions можно сохранить и использовать через совместимый
endpoint, но прямое **Подключить ChatGPT** для него недоступно. Messages или
маршрут через Relay не выдаются за нативный Responses.

## Что отображается

**Подключения** хранит источник и его несекретные настройки. **Обзор** показывает
модели, баланс, расходы и счётчики, если провайдер их предоставляет. Разделы
**Пул**, **API и ChatGPT** и **Использование** скрыты: маршрутизация и журнал
запросов принадлежат провайдеру.

## Цены и модели

Сначала Relay использует цены из каталога провайдера, затем проверенный общий
каталог, затем явную цену источника. Своя цена меняет только локальную оценку
API-эквивалента, а не счёт провайдера.

В режиме **Автоматически** список моделей обновляется при сохранении и ручном
обновлении источника. В режиме **Вручную** укажите ID моделей, если `/models`
недоступен; Relay сохраняет этот список и не проверяет его в фоне. Ручной
каталог — это утверждение оператора: проверьте модель и протокол у провайдера,
а неподдержанный запрос всё равно может завершиться ошибкой. Режимы
размышления — данные каталога или ручные правила пула; отдельная проверка
запросом не выполняется, и провайдер может отклонить вручную разрешённый режим.

## Если подключение не работает

| Симптом | Что проверить | Действие |
| --- | --- | --- |
| 401 Unauthorized | Ключ, срок действия и сервис, выдавший его. | Создайте или введите новый ключ. |
| 404 или нет моделей | Корень API и протокол. | Уберите путь конкретной модели и проверьте /v1. |
| 429 Too Many Requests | Баланс и лимит провайдера. | Подождите, пополните баланс или выберите другой источник. |
| **Подключить ChatGPT** недоступно | Протокол источника. | Включите нативный маршрут Responses API. |
| Модель есть, но отклоняется | Поддержка модели и параметров провайдером. | Сверьтесь с документацией провайдера. |
| В Обзоре нет баланса | Провайдер не отдаёт статистику. | Смотрите кабинет провайдера; ключ может работать. |
| ChatGPT использует старый адрес | Активный профиль. | Подключите нужный источник ещё раз. |

## Ключи и возврат

API-ключ хранится в системном защищённом хранилище и повторно полностью не
показывается. Он не попадает в снимки, диагностику, экспорты и журнал.

Чтобы вернуться к прошлому профилю ChatGPT, переключитесь в **Этот компьютер**,
откройте **Восстановление** и верните автоматическую точку или именованный снимок.
