# Этот компьютер

> Личный пул работает на этом компьютере. Zenith Relay должен быть запущен,
> пока ChatGPT или другой клиент отправляет запросы через локальный API.

**Подходит:** для личной работы, проверки аккаунтов и настройки пула без
отдельного сервера.

**Не подходит:** если API должен работать после выключения компьютера или
закрытия Zenith Relay. Для этого используйте режим **Мой сервер**.

## Как устроен режим

1. В **Подключениях** хранятся аккаунты ChatGPT, API-источники и прокси.
2. В **Пуле** выбираются участники, которым разрешено получать запросы.
3. Раздел **API и ChatGPT** запускает локальный OpenAI-совместимый адрес и
   подключает к нему ChatGPT.
4. **Использование** показывает запросы, модели, участника, скорость, токены и
   расчётный API-эквивалент.

Аккаунт вне пула продолжает проверяться, но не участвует в маршрутизации.
Аккаунт в пуле получает запросы только когда его сессия, модель и квота
доступны. Тариф **Free** не исключается автоматически.

Relay разрешает передавать изображения маршрутизируемым моделям, не угадывая
поддержку по их названиям. Окончательное решение принимает выбранная модель;
возможности нативных моделей ChatGPT не изменяются.

## Вкладки приложения

- **Обзор** показывает состояние среды и график **Скорость E2E**. Это все
  сообщённые выходные токены за время запроса Relay к провайдеру: ожидание
  первого вывода и сеть входят в измерение.
- **Подключения** хранит аккаунты, API-источники и прокси.
- **Пул** определяет, кто может принимать запросы, и задаёт правила моделей,
  порядок и вес маршрутизации.
- **API и ChatGPT** запускает локальный OpenAI-совместимый endpoint и обратимо
  подключает его к профилю ChatGPT/Codex. В этом режиме приложение должно быть
  открыто.
- **Использование** не хранит тексты запросов и содержит четыре вида:
  **Запросы**, **Модели**, **Участники пула** и **Ошибки**. Здесь **Скорость
  генерации** использует оставшиеся токены после первого вывода и исключает
  отдельно сообщённые reasoning-токены. Поле **Первый / всего** показывает
  время до первого вывода и полную длительность запроса.
- **Восстановление** возвращает сохранённый профиль, а **Помощь** объясняет
  выбранный режим и запускает повторную настройку.

## Что подготовить

- Zenith Relay и ChatGPT установлены на одном компьютере.
- Есть хотя бы один действующий аккаунт ChatGPT или совместимый API-источник.
- Если используется прокси, его адрес и авторизация уже проверены.
- Перед переключением профиля разрешено создать резервную копию.

## Первая настройка

### 1. Добавьте аккаунт

Откройте **Подключения** и выберите один способ:

- **Войти в ChatGPT** — откроется OAuth-вход в браузере;
- **Импортировать текущий профиль** — используется уже выполненный вход;
- **Импорт** — загружается поддерживаемый JSON или файл сессии.

После добавления дождитесь состояния **Обновлено**. Состояния **Ожидает
проверки** и **Проверяется** нормальны сразу после импорта. Если показано
**Требуется вход**, повторите авторизацию до добавления аккаунта в рабочий пул.

### 2. Соберите пул

Откройте **Пул** и добавьте нужные аккаунты и API-источники. Проверьте:

- участник включён;
- нужная модель доступна;
- прокси не сообщает ошибку;
- квота не исчерпана;
- порядок и правила маршрутизации соответствуют вашей задаче.

Не добавляйте один аккаунт повторно: импорт обновляет существующую запись по
идентификатору.

### 3. Запустите локальный API

Откройте **API и ChatGPT** и нажмите **Запустить API**. Адрес отображается в
этом же разделе. При стандартном порте он выглядит так:

```text
http://127.0.0.1:14998/v1
```

Изменяйте порт в этом разделе, а не вручную в файлах конфигурации.

### 4. Подключите ChatGPT

Выберите аккаунт для интерфейса ChatGPT или автоматический вариант, затем
нажмите **Подключить ChatGPT**. Перед изменением профиля Relay создаёт точку
возврата, если напоминание о резервной копии не отключено в настройках.

## Как проверить работу

1. Убедитесь, что в **API и ChatGPT** показано состояние **API работает**.
2. Отправьте короткий запрос из ChatGPT.
3. Откройте **Использование** и найдите новый запрос.
4. Проверьте модель, участника пула, HTTP-статус, время ответа и **Источник
   ошибки**, если запрос завершился неуспешно.
5. Вернитесь в **Пул** и убедитесь, что состояние аккаунта не стало красным.

> **Готово, если:** запрос успешен, в журнале указан реальный участник пула, а
> квота обновляется без ручного перезапуска приложения.

## Ежедневная работа

- Добавляйте в пул только тех участников, которым разрешено принимать трафик.
- Используйте кнопку обновления конкретного аккаунта для точечной проверки.
- Массовое обновление проверяет все включённые локальные аккаунты, а не только
  участников пула.
- Смотрите причину выбора участника в сведениях о запросе.
- Останавливайте локальный API перед изменением порта или обслуживанием данных.

## Если запросы не проходят

| Симптом | Что проверить | Что сделать |
| --- | --- | --- |
| **Требуется вход** | Сессия отозвана или токен недействителен | Повторно войдите в этот аккаунт |
| **Недоступно** | Последнюю ошибку квоты, моделей или прокси | Откройте состояние аккаунта и исправьте указанную причину |
| **429** | Квоту аккаунта, лимит модели и других участников | Дождитесь сброса или включите доступный резерв; один 429 не должен блокировать весь пул |
| Запрос не прошёл после выбора участника | **Источник ошибки** в Использовании | **Провайдер** отклонил запрос выше по цепочке, **Аккаунт** указывает на его учётные данные или маршрут, **Relay** - на локальную настройку или преобразование протокола |
| Модель не выбирается | Доступность модели у каждого участника | Обновите модели; не включайте модель вручную для аккаунта, который её не поддерживает |
| Запроса нет в журнале | Адрес клиента и состояние API | Повторно подключите ChatGPT и проверьте локальный адрес |
| Профиль ChatGPT изменился неверно | Последнюю автоматическую копию | Откройте **Восстановление** и верните предыдущий профиль |

## Восстановление и данные

**Сессии и ключи** находятся в защищённом хранилище операционной системы.
SQLite хранит несекретные записи, квоты, настройки и статистику запросов.

Раздел **Восстановление** возвращает конфигурацию и доступные файлы профиля
ChatGPT. Восстановление именованной точки требует подтверждения. По умолчанию
Relay предлагает сначала сохранить текущий профиль; это можно отключить для
одного восстановления или изменить значение по умолчанию в настройках. При
автоматическом отключении или восстановлении, управляемом Relay, изменённый
вами или Codex общий уровень размышлений сохраняется. Явно выбранное полное
восстановление снимка может вернуть снимок целиком; это исключение не входит
в данное обещание. Изменения провайдера, адреса, учётных данных или каталога
моделей блокируют управляемое восстановление для проверки, а не
перезаписываются.
Удаление аккаунта из приложения также удаляет принадлежащие ему локальные
секреты и связанные служебные данные.

Этот режим работает локально: секрет сессии не загружается в production-системы
Zenith, Gateway или Control API. Если позже выбрать **Мой сервер**, секрет
пользователя можно передать только на явно выбранный и подтверждённый сервер,
которым управляет тот же пользователь. Снимки, телеметрия, экспорты,
диагностика и локальное состояние API остаются обезличенными и не должны
содержать исходные ключи, cookies, промпты или тела ответов провайдера.
