# Zenith Relay

Relay подключает ChatGPT, OpenCode и другие совместимые приложения к вашим
аккаунтам и API-провайдерам. В пуле можно объединить несколько подключений:
приложение отправляет запрос на один адрес, а Relay выбирает, кто его выполнит.

## Как работает Relay

- **Подключения** хранят ваши аккаунты, адреса API и ключи провайдеров.
- **Пул** определяет, какие из этих подключений могут выполнять запросы и
  какие модели им разрешены. Участником может быть аккаунт или API-провайдер.
- **API** даёт приложению адрес пула и ключ для доступа к нему.

Приложение выбирает модель. Relay ищет участников, которым разрешена эта
модель и которые поддерживают формат запроса, затем применяет режим ротации.
Другой участник должен уметь выполнить тот же запрос: похожее название модели
не делает его подходящей заменой.

Сохранить подключение, включить его в пул и подключить приложение к пулу:
это три отдельных действия. При добавлении можно сразу включить участие в
пуле, но стоит проверить его в разделе **Пул**.

### Режимы работы

- **Компьютер**: пул работает на этом устройстве. Для запросов нужны запущенные
  Relay и его API. Этот режим подходит для нескольких личных аккаунтов и API.
- **Выбор API**: приложение подключается напрямую к выбранному внешнему API.
  Разделы **Пул**, **API** и **Использование** скрыты, ротация Relay не участвует.
  Данные в обзоре приходят от выбранного провайдера, если он их предоставляет.
- **На своём сервере**: пул работает в вашем Relay Server. Desktop-приложение
  управляет им и показывает его данные; после закрытия Relay сервер продолжает
  работу. Доступность действий зависит от возможностей подключённого сервера.

Переключение режима само по себе не переносит аккаунты и секреты. Для переноса
аккаунтов на свой сервер предусмотрено отдельное подтверждаемое действие.

### Быстрый старт

1. Выберите режим **Компьютер**.
2. В **Подключениях** войдите в ChatGPT, импортируйте свой аккаунт или добавьте
   API-провайдера. Дождитесь проверки и получения моделей.
3. В **Пуле** добавьте нужные подключения в участники. Убедитесь, что нужная
   модель разрешена и у участника, и во вкладке **Правила моделей**.
4. В разделе **API** нажмите **Запустить API**, если он ещё остановлен.
5. Вернитесь в **Пул → Подключить** и выберите ChatGPT или OpenCode. Для другого
   совместимого приложения скопируйте адрес и API-ключ из раздела **API**.
6. Отправьте запрос из приложения. В **Использовании** появится запись с
   моделью, участником и результатом.

В **Помощи** кнопка **Повторить быструю настройку** снова открывает мастер.
Для прямого подключения одного провайдера используйте **Выбор API** или
кнопку **Запустить** у API-источника, а не подключение к пулу.

## 1. Обзор

**Обзор** показывает состояние выбранного режима: адрес, доступные модели,
участников, запросы и скорость. Период графиков и область просмотра выбираются
отдельно. Статистика одного аккаунта или API относится только к нему.

### Баланс и оценки

У API могут отдельно показываться **Баланс**, **Остаток ключа** и **Остаток
подписки**. Это разные ограничения: **Без лимита** у ключа не означает
бесконечный баланс. Валюты и единицы сохраняются по данным провайдера;
разные валюты не складываются.

**Обновить баланс** в карточке пула или **Обновить** в обзоре выбранного API
запрашивает свежие данные. **Нет API баланса** означает, что Relay не нашёл
поддерживаемого способа получить статистику, а **Нет доступа к балансу**
означает отказ в её чтении. В обоих случаях запросы к моделям могут работать.
При неудачном обновлении последняя сумма остаётся с пометкой **Не обновлено**.

**Оценка Relay** и **API-экв. использ.** рассчитываются по запросам, которые
прошли через Relay, и доступным ценам. Это оценка стоимости использования,
а не баланс или подтверждённое списание провайдера. **API-экв. остаток**
появляется только при достаточных данных о недельном окне и использовании.
**Окупаемость** сравнивает использованный API-эквивалент с указанной ценой
покупки аккаунта. Активность вне Relay в эти оценки не входит.

## 2. Подключения

### Аккаунты и квота

В локальном режиме аккаунт можно добавить через вход в браузере или импорт
своего файла. В **Подключениях** также настраиваются прокси. Добавленный
аккаунт можно хранить без участия в пуле.

**Обновить** проверяет состояние и квоту у провайдера. Эта проверка не
пополняет квоту и не сбрасывает её окно. Длительность окна, остаток и время
восстановления задаёт провайдер. Если он не сообщил дату, Relay не может её
определить. Дата окончания подписки сама по себе не запрещает ротацию:
учитываются фактический доступ, вход, квота и ошибки аккаунта.

**Кредиты** на запросы и **кредиты сброса** различаются. Свежие данные о
доступных кредитах на запросы могут разрешать работу даже при нулевой
процентной квоте. Кредит сброса только позволяет выполнить отдельную операцию
сброса. **Сбросить недельную квоту** появляется у локального аккаунта при
доступном кредите, требует подтверждения и расходует этот кредит провайдера.

При статусе **Требуется вход** войдите в нужный аккаунт снова. Действие
**Принудительно обновить вход** проверяет возможность обновить сохранённую
сессию; отозванный вход оно не заменяет новым. Остальные подходящие участники
пула могут продолжать работу.

Экспорт аккаунта содержит данные для входа: храните этот файл как секрет.
Он отличается от пресета пула, который содержит только настройки.

### API-источники

Добавьте название, адрес API и ключ провайдера. Используйте адрес API из
документации, а не ссылку на кабинет. Полный endpoint, например `/v1/messages`,
также задаёт подсказку формата. Relay получает каталог и сведения о доступных
эндпоинтах. В локальном режиме при недоступном получении списка можно указать
ID вручную; это не добавляет провайдеру поддержку этих моделей.

В окне редактирования API-источника:

- **Основное**: название, адрес, замена ключа и определённые форматы.
- **Настроить адаптеры**: автоматический или ручной выбор маршрутов. Вручную
  доступные форматы провайдера назначаются каждой модели отдельно для каждого
  формата приложения. Несколько путей к одной модели разрешены. Преобразование
  выполняется через пул.
- **Цены**: цены для оценки использования; подробнее в разделе о правилах пула.

Новые источники используют автоматический выбор. Маршруты задают настройки
известного сервиса, явно вставленный endpoint или сведения провайдера.
Сам список моделей не доказывает поддержку генерации: неизвестный источник
сохраняет каталог и ждёт проверки либо ручного выбора. У старых источников
остаются сохранённые ручные маршруты.
**Проверить генерацию** отправляет один небольшой тестовый текстовый запрос
выбранной модели в выбранном формате провайдера и может расходовать квоту.
Он подтверждает только текстовую генерацию, а не инструменты, изображения
или все уровни размышлений. Обновление каталога запросов к модели не делает.
Перед проверкой сохраните изменённые адрес и ключ: прежние результаты
становятся недействительными. Ошибка входа, таймаут или 5xx не доказывают
отсутствие формата. HTTP 404/405 отключает только проверенную пару модель/формат.

Кнопка **Запустить** у источника подключает выбранное приложение напрямую
к этому API. Такой запрос обходит пул, его ротацию и журнал использования
Relay. Для прямого ChatGPT/Codex нужен нативный Responses. OpenCode использует
SDK нативного формата источника: Responses, Chat Completions, Messages или Gemini.
Наличие модели в общем списке ещё не означает совместимость с клиентом.

### Автоматизации

В **Подключения → Автоматизации** локальный режим предлагает два условия:

- **После восстановления основной квоты**: небольшой запрос к выбранной модели
  после восстановления окна, чтобы запустить отсчёт его следующего сброса,
  если провайдер использует такой механизм. Запрос расходует квоту. Можно
  выбрать автоматическое выполнение или ручной запуск готовых проверок.
- **Автосброс недельной квоты**: при исчерпании недельного окна Relay пытается
  применить доступный кредит сброса провайдера. Отдельный запрос к модели для
  этого не нужен. Включение автоматизации разрешает последующие сбросы без
  отдельного подтверждения каждого из них.

Выберите аккаунты и включите задачу. Локальные автоматизации выполняются,
пока работает Relay; серверные зависят от возможностей Relay Server.

### Свой сервер

Сохраните адрес Relay Server и его токен управления во вкладке подключения
сервера. Токен нужен desktop-приложению для управления, а клиенту моделей
нужны адрес API и отдельный ключ запросов. Не меняйте их местами.

Перенос аккаунта на сервер выполняется отдельным действием с подтверждением.
После успешного переноса он участвует в серверном пуле; локальная запись
остаётся для восстановления и не получает локальные запросы.

## 3. Пул

### Участники и выбор маршрута

В **Участниках** добавляйте сохранённые подключения и открывайте их правила.
Убрать подключение из пула можно без удаления из **Подключений**. Выключенный
участник, аккаунт с требованием входа, запрещённым доступом или недоступной
квотой пропускается. Его присутствие не запрещает выбор остальных.

Доступность всегда проверяется для конкретной модели и формата запроса.
Поэтому рабочий пул может не иметь маршрута для одной из моделей. Если
провайдер временно ограничил только модель, это не обязательно блокирует
остальные модели этого участника.

**Ротация пула** содержит три режима:

- **Умный выбор** учитывает текущую нагрузку, свежую квоту и недавние ошибки.
  Между сопоставимо подходящими участниками запросы распределяются с учётом
  доли запросов. Ручной порядок здесь не влияет на выбор. Предпочтение
  подключения ради кэша допускается только среди сопоставимо подходящих.
- **По порядку** выбирает первого подходящего свободного участника в вашем
  списке. Если он недоступен или занят до лимита, Relay проверяет следующих.
  После его восстановления новые запросы снова идут к нему. Только в этом
  режиме доступна ручная перестановка участников.
- **По кругу** распределяет новые независимые запросы между подходящими
  участниками с учётом доли запросов. При одинаковых долях они чередуются;
  недоступные или занятые до лимита участники пропускаются.

Во всех режимах продолжение чата может требовать прежнего участника. Поэтому
ротация не обещает менять аккаунт на каждом сообщении одного разговора.

Режим, порядок, доля и лимит запросов сохраняются сразу. В режиме **По порядку**
перетаскивайте участника за ручку или используйте стрелки. **Закрыть** дожидается
сохранения. При изменении состава пула список обновляется автоматически.
Если сохранить не удалось, появится ошибка и вернутся сохранённые значения.

**Доля запросов** задаёт соотношение для умного выбора и режима по кругу.
Например, 2 и 1 дают примерно две части трафика первому и одну второму при
одинаковой доступности. Это не процент, скорость запросов или увеличение квоты.
**Одновременных запросов** ограничивает число запросов к одному участнику в
один момент, суммарно по его моделям и форматам. Значение 2 допускает два
запроса одновременно. **Без лимита** снимает ограничение со стороны Relay,
но не ограничения провайдера.

Карточки группируются по готовности, ожиданию квоты, недоступности и отключению.
В окне ротации режим **По порядку** сохраняет ручную очередь даже при смене
статусов; в остальных режимах сначала видны готовые участники.
**Текущий**, последний использованный и **Следующий кандидат** отвечают на
разные вопросы. Следующий кандидат показан только тогда, когда выбор для
нового текстового запроса совпадает у включённых моделей и форматов.
Отсутствие этой подсказки не означает, что пул остановлен.

### Ошибки и повторные попытки

Восстановление работает автоматически. Relay перебирает всех совместимых
участников перед возвратом ошибки кандидата. Временный сбой приостанавливает
маршрут минимум на 5 секунд; доступный участник может принять запрос сразу.
При необходимости Relay делает один повторный проход в пределах 30 секунд.
Повторный сбой даёт паузу 60 секунд, затем она удваивается до 30 минут.
Пауза действует и для последнего кандидата. Успех сбрасывает счётчик сбоев.
Указанный провайдером срок повтора или сброса квоты и более длинная пауза
участника обязательны. Ошибки входа, доступа к модели и исчерпанная квота
сразу переводят запрос к следующему доступному участнику. Сбой конкретной
модели не отключает остальные модели источника.

После паузы один запрос проверяет восстановление участника. Остальные
используют другой подходящий маршрут или ждут проверку либо свободное место
до 30 секунд. Для ChatGPT есть отдельное длительное ожидание в
**API → ChatGPT → Ожидать восстановления маршрута**.

Relay может повторить запрос у другого участника до начала передачи ответа
приложению. Уже начатый ответ не смешивается с ответом другого провайдера.
Продолжение разговора можно перенести только при достаточной сохранённой
истории. Ссылка на ответ или результат инструмента без нужного контекста
может требовать прежнего участника; Relay не отбрасывает такой контекст молча.
Ошибки самого запроса, например превышение контекста или неверный вызов
инструмента, перебором участников не исправляются.

### Модели и правила участника

В **Правилах участника пула → Модели** переключатель разрешает модель для
конкретного аккаунта или API. Это разрешение, а не индикатор его квоты.
Поиск и раскрывающиеся группы помогают найти нужную модель.

Во вкладке пула **Правила моделей** модель включается или выключается для
всего пула. Здесь также задаются порядок моделей и групп, доступные режимы
размышлений и скорость для модели. Порядок моделей влияет на представление
каталога, а порядок участников в ротации определяет выбор подключения.
Список моделей приложения дополнительно ограничен совместимостью клиента.

**Скорость запроса** имеет варианты **Обычная**, **Быстрая** и **Сверхбыстрая**.
Общее предпочтение задаётся над участниками; для отдельной модели можно
сохранить своё. Быстрые режимы используются при подтверждённой поддержке
выбранной моделью и источником. Если сверхбыстрый недоступен, Relay выбирает
поддерживаемый быстрый или обычный режим. Это пожелание к обработке запроса,
а не гарантия времени ответа, дополнительная квота или режим ротации.

### Цены и дополнительные настройки

Цены API находятся в **Правилах участника пула → Цены** и в окне редактирования
источника в **Подключениях**. Для оценки сначала используется цена провайдера,
затем подходящая цена каталога, затем ручная цена при отсутствии первых двух.
Ручная цена не меняет тариф провайдера и не имеет безусловного приоритета.

Цены токенов указаны в USD за миллион. В ручном наборе обязательны вход и
выход; кнопка сброса удаляет ручной набор. Поля записи кэша на 5 минут и час
появляются для подходящих моделей и форматов. Они задают стоимость записи
кэша с таким сроком хранения, а не включают кэширование запроса.

В **Настройках** участника у аккаунта доступны **Не назначать запросы**
и **Цена покупки, USD**. Первая настройка прекращает назначение новых запросов;
вторая нужна только для оценки окупаемости. У API настраивается пауза после
ошибок: автоматически или вручную. Она не сокращает обязательное время
ожидания, указанное провайдером. Нажмите **Сохранить правила** для применения;
**Отмена** отбрасывает правки окна.

**Сохранить пресет** и **Применить пресет** переносят настройки состава,
ротации и моделей. Пресет не содержит ключей, входов, реального остатка квоты
или истории запросов. Перед применением Relay показывает изменения и
сопоставляет участников с уже существующими подключениями.

## 4. API

### Адрес и ключ для приложения

Во вкладке **API** этого раздела видны состояние, адрес и действия запуска.
Скопируйте показанный адрес. Обычно локальный адрес:

```text
http://127.0.0.1:14998/v1
```

**Копировать API-ключ** копирует ключ запросов к Relay. Это не ключ внешнего
провайдера и не токен управления сервером. **Перевыпустить API-ключ** сразу
делает прежний ключ недействительным: после этого обновите ключ в клиентах.
Обычное копирование ключ не меняет. После изменения порта также обновите
адрес или заново подключите приложение.

Все четыре формата используют один ключ пула и одинаковые права на модели:

| Формат | Локальный endpoint | Авторизация |
| --- | --- | --- |
| Responses | `http://127.0.0.1:14998/v1/responses` | Bearer-ключ |
| Chat Completions | `http://127.0.0.1:14998/v1/chat/completions` | Bearer-ключ |
| Messages | `http://127.0.0.1:14998/v1/messages` | `x-api-key` или Bearer-ключ |
| Gemini | `http://127.0.0.1:14998/v1beta/models/{model}:generateContent` | `x-goog-api-key` или Bearer-ключ |

Для потока Gemini используется `:streamGenerateContent?alt=sse`. В серверном
режиме подставьте адрес своего сервера. В **Пул → Правила моделей** значок
маршрута открывает доступность каждого формата приложения, состояние функций
и уровни размышлений на маршруте. «Не проверено» не означает обещание поддержки.
Неподдерживаемые параметры преобразования отклоняются до генерации; нативные
маршруты сохраняют расширения провайдера. Realtime, межформатный WebSocket,
преобразование аудио/видео и эмуляция серверных инструментов не предлагаются.

### ChatGPT

Во вкладке **ChatGPT** настройка **Аккаунт ChatGPT** определяет вход,
используемый интерфейсом приложения: автоматически, выбранный аккаунт или
**Без аккаунта**. Нажатие **Переключить** применяет выбор и перезапускает
ChatGPT. Это отдельная настройка от ротации: запросы к моделям через адрес
пула всё равно распределяются между его подходящими участниками.

**Резерв 1%** сохраняет последний процент выбранного аккаунта для прямого
запуска ChatGPT, ограничивая его использование пулом. Это не общий резерв
каждого участника и не настройка баланса API-провайдеров.

- **Фоновые задачи ChatGPT** разрешают автоматические сводки активности
  и заголовки задач. Они могут выполнять отдельные запросы.
- **WebSocket для ChatGPT** управляет способом подключения клиента. Включение
  может потребовать перезапуска ChatGPT и прервать текущий запрос. Поддержка
  WebSocket у внешнего провайдера от этой настройки не появляется.
  Если каталог содержит маршруты с преобразованием Responses, автоматически
  используется HTTP/SSE. Нативные маршруты сохраняют WebSocket, когда каталог
  позволяет этот транспорт.
- **Ожидать восстановления маршрута** удерживает распознанные запросы ChatGPT,
  когда подходящие участники временно недоступны, до восстановления или отмены.
  Без этого после обычных попыток клиент получает ошибку. Ожидание не
  исправляет неверный запрос и не отменяет требования к истории продолжения.

Для серверного пула во вкладке ChatGPT используется подключение к вашему
серверу, если он поддерживает эту возможность.

### OpenCode

В локальном режиме подключите OpenCode через **Пул → Подключить → OpenCode**.
Relay подготовит подключение и совместимый каталог моделей. Для одного API
используйте **Запустить** у источника. Модели распределяются по SDK их нативных
форматов. Рабочие ID подключений и моделей, выбранная модель и пользовательские
настройки сохраняются. Обновление каталога меняет только группы Relay с прежними
адресом, ключом и SDK и не перезапускает OpenCode. Исходная конфигурация остаётся
доступна для восстановления. Вкладка **API → OpenCode** пока помечена
**В разработке**; отдельной панели настроек интеграции в ней ещё нет.

## 5. Использование

Здесь показаны запросы, прошедшие через выбранный локальный или серверный пул.
Прямые запросы к API-провайдеру и активность аккаунта в других приложениях
в этот журнал не попадают. Фильтр периода меняет отображение, а не удаляет записи.

Откройте запрос, чтобы увидеть модель, участника, формат, время до первого
вывода, общее время, токены и оценку стоимости. Запрошенные параметры
размышлений и скорости могут отличаться от фактически переданных; смотрите
соответствующие поля. Неизвестные показатели не означают нулевую стоимость.

У ошибки отдельно показаны **Источник ошибки**, категория Relay и сохранённые
код, HTTP-статус и очищенное сообщение провайдера. В старых записях сообщение
может отсутствовать. Журнал не сохраняет тексты запросов и ответов или секреты.

## 6. Восстановление

Раздел доступен в режиме **Компьютер** и относится к конфигурации клиентских
приложений на этом устройстве.

**Снимки ChatGPT** сохраняют именованную копию конфигурации и состояния входа.
Восстановление выбранного снимка заменяет текущие настройки и вход его
содержимым. Это явный возврат к сохранённому состоянию, поэтому проверяйте
название и дату снимка.

Автоматическая копия перед подключением ChatGPT к Relay существует отдельно.
Отмена управляемого подключения сохраняет посторонние настройки и отказывается
перезаписывать более новый ручной вход. Это отличается от явного
восстановления полного снимка.

Для OpenCode хранится исходный снимок конфигурации, созданный вручную или
перед первым подключением. Он сохраняется до восстановления; повторное
подключение не создаёт историю новых снимков. Восстановление снимка и сброс
всех данных Relay являются разными действиями.

## 7. Настройки

В **Внешнем виде** меняются язык и тема. Помощь следует выбранному языку.
В **Приложении** можно проверить версию, обновления и открыть папку рабочих
данных; показанный путь соответствует этому устройству.

В **Данных пула** настройка **Напоминать о точке возврата** управляет
подтверждением перед переключением ChatGPT. Автоматическая защищённая копия
создаётся и при отключённом напоминании.

Для поиска проблемы включите **Режим отладки**. Появится **Диагностика**
с доступом к журналам ошибок, падений и этапов операций. Ошибки и падения
записываются и без отладки; подробные этапы нужны на время проверки.

**Сбросить данные локального пула** сначала пытается безопасно восстановить
управляемый профиль ChatGPT, затем удаляет локальные аккаунты, источники,
настройки и использование. Если восстановление невозможно, удаление не
выполняется. Для исправления одного подключения полный сброс не требуется.

## 8. Ошибки

Откройте ошибку карточки или запрос в **Использовании**. Смотрите вместе
**Источник ошибки**, категорию Relay, код провайдера и HTTP-статус.
Например, `invalid_api_key` может относиться к ключу самого пула или к ключу
внешнего API. Исправлять нужно подключение, указанное в деталях.

Ниже перечислены коды Relay и распознаваемые им ситуации. Произвольное
сообщение внешнего провайдера может отличаться; для него сохранены очищенные
детали. `exceeded retry limit` означает, что клиент исчерпал повторы:
причину показывает последняя ошибка, например 429. Увеличение повторов
не восстанавливает квоту.

### Если код не найден

Внешние провайдеры могут добавлять свои коды. Откройте детали запроса:
сохранённый код и сообщение провайдера точнее общего HTTP-статуса.
Если после начала ответа произошёл обрыв, Relay не смешивает частичный ответ
с новым ответом другого участника. Для продолжения может понадобиться
полная история или исходное подключение.

Для обращения за помощью укажите версию Relay, режим работы, действие,
модель, HTTP-статус, источник ошибки, код и ID запроса. Очищенные детали
и журналы доступны в **Использовании** и **Настройках → Диагностика**.
Не отправляйте ключи, cookies, файлы входа, экспорты аккаунтов или разговоры.
