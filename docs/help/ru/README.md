Zenith Relay — локальное desktop-приложение для управления личными аккаунтами
ChatGPT и совместимыми API. Оно может отдавать разрешённые и реально доступные
модели через один приватный OpenAI-совместимый адрес и обратимо подключать этот
адрес к ChatGPT/Codex.

## С чего начать

Для каждого режима есть отдельная полная инструкция:

| Режим | Где работает | Инструкция |
| --- | --- | --- |
| **Этот компьютер** | Личный пул и `/v1` работают внутри desktop-приложения. | [Открыть](this-computer.md) |
| **Выбор API** | ChatGPT подключается напрямую к выбранному совместимому API. | [Открыть](choose-api.md) |
| **Мой сервер** | Личный пул работает на вашем Relay Server. | [Открыть](my-server.md) |

Для первой проверки личных аккаунтов используйте **Этот компьютер**. Режим
**Мой сервер** нужен, когда API должен работать после закрытия приложения.
Выбирайте режим **Выбор API**, если уже есть готовый API-ключ и пул аккаунтов не
требуется.

## Установка

Скачайте пакет для своей платформы на странице
[GitHub Releases](https://github.com/F0RLE/zenith-relay/releases/latest).
В Windows обычно выбирайте **Setup**; portable EXE запускается без установки.
Для Linux публикуются AppImage, DEB и RPM, для macOS — DMG под Intel и Apple
Silicon.

При первом запуске быстрая настройка предложит выбрать режим, подключение и
профиль клиента. Если найден подходящий уже выполненный вход ChatGPT,
**Импортировать текущий профиль** добавит его в локальный пул и после короткого
подтверждения откроет выбор клиента. Повторно открыть мастер можно из раздела
**Помощь**.

## Разделы приложения

- **Обзор** показывает состояние запуска, доступную ёмкость, баланс/статистику,
  когда источник их предоставляет, и последние события.
- **Подключения** хранит входы ChatGPT или импортированные сессии, совместимые
  API, прокси и управляющее подключение к серверу.
- **Пул** управляет включёнными участниками, дренированием, правилами моделей,
  порядком, весом и стратегией маршрутизации.
- **API и ChatGPT** запускает личный endpoint и подключает выбранный адрес к
  ChatGPT/Codex.
- **Использование** показывает статус, участника, модель, токены, задержки,
  скорость генерации и оценку API-эквивалента, не сохраняя обычные тексты
  промптов и ответов. Скорость E2E с полным временем запроса находится в
  **Обзоре**.
- **Восстановление** возвращает снимок профиля или удаляет только настройки
  Relay, не перезаписывая постороннюю конфигурацию пользователя.
- **Помощь** отображает эти же локализованные инструкции внутри приложения.

## Маршрутизация и квоты

Мониторинг и маршрутизация разделены. Включённый аккаунт можно проверять вне
пула, но для запроса он должен быть включён в пул, не находиться в дренировании,
иметь рабочую сессию и прокси, поддерживать выбранную модель, быть здоровым и
иметь доступную квоту.

Окна квоты берутся из данных провайдера. Relay не придумывает единый лимит на
пять часов или неделю. Повтор через другого участника разрешён только до
отправки байтов клиенту. Affinity ответа или промпта не заставляет использовать
недоступный аккаунт.

## Конфиденциальность и восстановление

На компьютере секреты находятся в системном хранилище учётных данных. На своём
сервере сессии и внутренние данные профиля хранятся в зашифрованном vault, а
рабочее состояние — в SQLite. Управляющий токен сервера и данные профиля имеют
разное назначение и не взаимозаменяемы.

Держите сервер за HTTPS, храните ключ vault отдельно от резервной копии каталога
данных и заранее проверяйте восстановление. Relay скрывает ключи, cookies,
заголовки авторизации, промпты и идентификаторы аккаунтов из обычной диагностики
и журнала использования.

## Текущие ограничения

- Сейчас выпущен только коннектор аккаунтов ChatGPT.
- Режим **Этот компьютер** останавливается вместе с desktop-процессом.
- Для режима **Мой сервер** ещё нужно пройти live-проверку из roadmap, прежде
  чем считать его готовым к production.
- Распределённые leases и prompt affinity между несколькими серверами не
  реализованы.
- Новые системы аккаунтов и клиенты добавляются только при наличии разрешённого,
  обратимого и проверяемого способа авторизации/настройки.
