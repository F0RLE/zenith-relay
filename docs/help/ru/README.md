# Zenith Relay

Relay помогает подключить установленное приложение ChatGPT, Claude Desktop,
OpenCode или другой API-клиент к вашим аккаунтам и API-источникам. Можно использовать один источник
напрямую или собрать пул, который выбирает доступное подключение для каждого
запроса. Переписка и работа с моделью остаются в выбранном приложении.

## Быстрый старт

Для начала нужен свой аккаунт или API-ключ провайдера и установленное приложение,
в котором вы будете работать. Relay не устанавливает ChatGPT, Claude Desktop или OpenCode.

### Подключить приложение через пул

1. Выберите режим **На устройстве**.
2. Добавьте хотя бы одно подключение:
   - аккаунт: **Подключения → Аккаунты → Войти → ChatGPT** или **Excel / Basis Points**,
     затем **Открыть окно входа**;
   - API: **Подключения → Источники API → Добавить источник**, выберите сервис
     и укажите его ключ.
3. Откройте **Пул → Участники → Добавить**. Отметьте сохранённое подключение
   и добавьте его в пул. Если подключение уже участвует в пуле,
   повторять этот шаг не нужно. Его карточка должна появиться в **Участниках**.
4. В **Пул → Правила моделей** проверьте, что нужная модель включена.
   Если её нет, обновите подключение и проверьте доступ к модели у провайдера.
5. В **Доступ → Локальный API** нажмите **Запустить API**.
   Должно появиться **API работает**.
6. Откройте **Пул → Подключить**, выберите ChatGPT, Claude Desktop или OpenCode.
   Claude Desktop получает точный список моделей пула в его текущем порядке через
   профиль стороннего inference. Relay проверяет подключение, закрывает открытый
   Claude Desktop и сохраняет профиль перед возможным запуском.
   По умолчанию приложение откроется после подключения. Чтобы отключить запуск,
   выключите **Настройки → Приложение → Запускать приложения после подключения**.
   Для другого клиента используйте
   [ручную настройку API](#локальный-api).
7. В приложении выберите модель и отправьте короткий запрос. В Relay откройте
   **Использование → Запросы**: там появятся результат и выбранный участник.

Для пула используйте **SIWC** или **Excel / BPS**; **Codex** только переключает
аккаунты приложения. При выборе Codex карточка выходит из пула, сохраняя входы
и **Заметки**. В **Подключения → Аккаунты** значок клиента выбирает маршрут.
**Подключить** открывает вход в тот же аккаунт и рабочую область с отдельными
авторизацией и квотой. Ротируется только выбранный маршрут с прежним весом
и параллельностью. Сначала завершите текущие запросы. Автоматизации следуют
за маршрутом; несовместимую явную модель сначала измените или выключите правило.
Вход маршрута использует **Заметки** карточки; новый аккаунт начинает с пустых.
Codex/BPS пробуют почту, пароль и необязательный секрет приложения 2FA
на Windows, macOS и Linux. Без заметок и для SIWC вход ручной.
Подробнее — [Вход в аккаунт](#вход-в-аккаунт).

На первом запуске мастер проведёт через выбор режима, подключения и клиента.
Его можно пропустить или повторить через **Помощь → Повторить быструю настройку**.
Выбор клиента в мастере настраивает его, но сам по себе не запускает приложение.
Claude Desktop идёт вторым в списке клиентов и доступен в режиме «На устройстве».

### Работать без пула

- **Codex:** **Запустить в ChatGPT** переключает аккаунт с нативными данными. SIWC/BPS работают только через пул.
- **API:** добавьте источник в **Подключения → Источники API**,
  нажмите **Запустить** и выберите приложение.

Прямые запросы обходят ротацию и журнал **Использование**. Вернуться к пулу
можно через **Пул → Подключить** в режиме **На устройстве**.

## Как работает Relay

При работе через пул запрос проходит путь:
**приложение → API Relay → подходящий участник → провайдер**.

- **Подключение** — сохранённый вход в аккаунт или адрес API с ключом.
- **Участник пула** — подключение, которому разрешено принимать запросы через Relay.
  Сохранить подключение и добавить его в пул — отдельные действия.
- **Модель** — точный идентификатор модели у провайдера. Похожее название
  не означает одинаковый доступ.
- **Клиент** — приложение, которое отправляет запросы. Его подключают к пулу
  после добавления участников.

### Режимы работы

| Режим | Когда выбирать |
| --- | --- |
| **На устройстве** | Пул и API работают на вашем устройстве. |
| **На сервере** | В разработке. |

В режиме **На устройстве** закрытие окна оставляет Relay в трее; полный выход
останавливает локальный API и автоматизации. Смена режима не останавливает API
и не переносит секреты.

### Установка на macOS

Переместите приложение из DMG в **Программы**. Сборка подписана ad-hoc и не
нотариально заверена. Если macOS блокирует первый запуск, выберите
**Системные настройки → Конфиденциальность и безопасность → Открыть всё равно**
для этого приложения. Не отключайте Gatekeeper для всей системы.

Если контрольная сумма релиза совпадает, но macOS сообщает о повреждении,
снимите карантин только с приложения:

~~~sh
xattr -dr com.apple.quarantine "/Applications/Zenith Relay.app"
~~~

## 1. Обзор

**Обзор** показывает активность пула, подключения, модели, ошибки и графики.
Выберите период и подключение; отдельные запросы смотрите в **Использовании**.

### Как читать графики

**Сегодня** показывает 24 часовых интервала, включая текущий; **Неделя** —
7 дней, **Месяц** — 30 дней. Время местное. Выбор подключения над графиками
ограничивает их данные этим аккаунтом или API-источником.

Верхние **Запросы** и **Ошибки** используют тот же фильтр; ошибки — все
учтённые неуспешные запросы. **Подключения** — число включённых аккаунтов и
API-источников, не гарантия их работоспособности. **Модели** — число моделей,
опубликованных API пула.

| График | Что означает |
| --- | --- |
| **Использование токенов** | Вход — инструкции, история и инструменты; выход — ответ модели, включая учтённые размышления. Чтение и создание кэша — части входа, их не нужно прибавлять повторно. Левая шкала показывает токены, правая — процент попаданий в кэш. |
| **Эквивалент API** | Оценка стоимости учтённого использования по API-ценам, не списание с подписки или баланс. Без известных цен оценка неполная. |
| **Запросы** | Число учтённых запросов за интервал, включая ошибки. Результат каждого запроса смотрите в **Использовании**. |
| **Скорость генерации** | Наблюдаемая скорость вывода после первого токена, без учтённых токенов размышлений; ток/с. Ожидание первого токена сюда не входит. |
| **Скорость E2E** | Выходные токены за полное время запроса, включая ожидание первого токена; ток/с. Поэтому её нельзя напрямую сравнивать со скоростью генерации. |

Цвета подписаны в легенде. Фиолетовый пунктир **Попадания в кэш** — доля
кэшированного входа, не остаток квоты или контекста. Заголовки дают итог периода;
скорость — суммарные токены/время, не среднее точек. Наведите указатель или
фокус на точку для точного значения. Разрыв или **—** — отсутствие измерения,
не ноль. Ошибки загрузки показываются предупреждением.

### Балансы и оценки

Провайдер сообщает баланс и квоту; Relay оценивает **Эквивалент API** по
использованию и известным API-ценам. Это разные величины, не счёт к оплате.

**Нет API баланса** — баланс недоступен, не нулевой. **Доступ к статистике
запрещён** — отказ чтения; запросы моделей могут работать. При ошибке обновления
сохраняется последнее значение с отметкой об устаревании.

## 2. Подключения

Здесь сохраняют аккаунты, API-источники и прокси, настраивают автоматизации.
Настройки поведения аккаунтов находятся отдельно: **Доступ → Аккаунты**.

### Вход в аккаунт

Откройте **Подключения → Аккаунты → Войти** и выберите способ:

- **Codex** — по умолчанию; переключение аккаунтов и показ квоты связанного SIWC, без участия в пуле.
- **ChatGPT (SIWC)** — окно входа Relay, работа через пул.
- **Excel / Basis Points** — пул, нужен платный тариф (BPS).

1. Нажмите **Открыть окно входа**.
2. Войдите в аккаунт. Relay сохранит его и закроет окно.
3. При необходимости добавьте аккаунт в **Пул** вручную.

У всех способов есть **Скопировать ссылку входа** для браузера на том же компьютере.

**Заметки** сохраняют почту, телефон, пароль и 2FA с аккаунтом. Черновик нового
аккаунта не теряется при сворачивании, удаляется при отмене и не заполняет форму входа.

Кнопка **Копировать** у пароля/секрета 2FA копирует значение целиком, не раскрывая
его. Для выделенного текста используйте **Ctrl+C** (**Cmd+C** на macOS)
или контекстное меню.

Для сохранённого **Excel / Basis Points** нажмите ПКМ на **Требуется вход**:
используются почта, пароль и необязательный секрет приложения 2FA из заметок.
ЛКМ оставляет ручной вход. На Windows, macOS и Linux используются профиль и
прокси аккаунта. CAPTCHA, дополнительные проверки, согласие, незнакомая форма,
ошибка или лимит 45 секунд открывают то же окно для ручного продолжения.
**Открыть окно входа** делает это в любой момент. Коды из почты/SMS и сторонние
сервисы остаются ручными. Перед сохранением Relay проверяет аккаунт;
добавление маршрута не переиспользует авторизацию другого клиента.

Для SIWC разрешите использование плана при входе. Счётчики Codex/BPS не подтверждают лимиты SIWC.
Если SIWC подтвердил исчерпание квоты до начала генерации, Relay ставит это
подключение на паузу и выбирает следующего допустимого участника пула.
После начала генерации или при неизвестном результате запрос не повторяется.
При повторном входе используйте тот же аккаунт и способ.
Крестик или Escape отменяют вход до сохранения.

### Импорт, экспорт и состояние аккаунтов

**Импорт** принимает файлы и вставленные данные. Сначала проверьте распознанные
записи, затем выберите нужные и подтвердите импорт. Файл можно перетащить в окно
Relay. Включайте **Сразу добавить выбранные в пул**, только если этого хотите:
опция применяется к допустимым подключениям пула и API-источникам, не Codex.
Записи Free BPS отклоняются и при выключенном добавлении в пул.
При частичной ошибке можно повторить только неудавшиеся записи.

Zenith сохраняет все три способа входа. Для SIWC доступен только Zenith;
после импорта войдите повторно перед использованием. Существующие подключения
SIWC не перезаписываются. Не используйте копии refresh-токена на двух устройствах.
Для BPS доступны Zenith и Sub2API.

На карточке видны тариф, квоты, сроки их сброса и состояние. **Обновить**
запрашивает новые данные; оно не пополняет квоту. Неизвестная квота не равна
нулю. Для SIWC отсутствующие тариф/квота берутся у связанного Codex/BPS только
для показа, не ротации; без источника отмечаются как непереданные. Подсказка
показывает источник и время; жёлтый означает устаревание. **Обновить** проверяет
этот источник без фоновых опросов.
Лимиты и кредиты обновляются независимо: активные запросы не делают
старый баланс свежим. Ротация использует только свежие сведения о кредитах;
сохранённый баланс остаётся видимым до нового полного опроса.
Только для BPS между квотой и датой подписки показаны значок
токена и время до истечения; точная дата доступна при наведении. Если срок
неизвестен, показано `—`. Истечение меняет только эту подпись: индикатор
не обновляет токен, не отключает аккаунт и не меняет участие в пуле.
Сохранённый refresh token позволяет обновить
истёкший access token перед следующим запросом; отозванный вход требует
повторной авторизации. Локальный срок токена не подтверждает доступ у провайдера.
Временную сетевую ошибку можно повторить позже. Восстановление сохраняет
ваше отключение аккаунта и его участие в пуле. Выполните повторный вход,
если карточка сообщает, что сессию больше нельзя обновить.
Данные аккаунта по умолчанию показаны частично; общий переключатель видимости
позволяет раскрыть их.

**Убрать из пула** сохраняет подключение, но прекращает новые назначения.
ЛКМ по **Удалить** в **Подключениях** перемещает учётную запись в **Корзину**.
Данные входа сохраняются, а запись перестаёт участвовать в пуле и фоновых задачах.
В **Подключения → Корзина** выберите **Восстановить**, чтобы вернуть её выключенной
и вне пула; при необходимости включите и добавьте её в пул вручную.
ПКМ по той же кнопке открывает меню **Удалить навсегда**. Выбор действия
запрашивает подтверждение, затем удаляет запись и её данные входа без
возможности восстановления. В корзине это действие находится внизу карточки.
Экспорт из меню карточки или выбранных аккаунтов содержит данные входа:
храните его как пароль, не прикладывайте к сообщению об ошибке.

### Часовые пояса аккаунтов

В **Подключения → Учётные записи** откройте
**⋯ → Часовой пояс аккаунта**. Вверху окна показан результат выбранного правила.

- **Авто** следует выбору **Часовой пояс по умолчанию** в
  **Доступ → Аккаунты → ChatGPT**. Изначально выбран назначенный прокси.
  Без его пояса Relay не меняет пояс в запросе. При выборе **Настройка аккаунта**
  используется сохранённый для аккаунта источник.
- **Задать** включает отдельную настройку аккаунта. Выберите источник:
  собственный пояс или назначенный прокси. Если выбран прокси, но у него
  нет пояса, подстановки не будет. Собственный пояс без сохранённого выбора —
  `America/New_York` (Нью-Йорк).
- **Не подставлять** сохраняет исходный пояс клиента, даже при наличии прокси.

Найдите город, IANA-пояс или смещение UTC и нажмите **Сохранить**.
Пояса отсортированы по текущему смещению UTC. Псевдонимы находятся поиском,
а разные правила перехода на летнее время остаются отдельными вариантами.
Выбранный пояс сохраняется при отключении подстановки.

Relay меняет уже существующие поля часового пояса в окружении запросов
и местоположении веб-поиска аккаунтов, включая HTTP и WebSocket.
Даты, обычный текст, системный часовой пояс и запросы API-источников сохраняются.
Переносимые пресеты не переносят привязки аккаунтов.

### Прокси

Прокси необязателен. В **Подключения → Прокси → Импортировать**
добавьте адреса по одному в строке, затем назначьте прокси аккаунту через
его настройки. Прокси для входа также можно выбрать кнопкой с замком в окне входа.

**Проверить прокси** показывает выходной IP, страну, задержку и время проверки.
Результат сохраняется после перезапуска, поэтому смотрите и на его дату.
Успешная проверка соединения не подтверждает доступ аккаунта к модели.
Если назначенный прокси не работает, Relay не обходит его прямым подключением.

Новые прокси проверяются автоматически, пояс определяется по выходному IP.
При открытии хранилища прокси без определённого пояса проверяются один раз.
Пояс появляется на карточке и применяется к следующим запросам привязанных
аккаунтов без сохранения и перезапуска Relay или приложения-клиента. Явные
настройки аккаунта, включая **Не подставлять**, сохраняют приоритет.
Проверка использует IPWhois через выбранный прокси и не передаёт токены аккаунтов.
Если сервис не вернул корректный пояс, Relay не угадывает его по стране;
позже результат можно обновить кнопкой **Проверить прокси**. Неудачная проверка
сохраняет известный пояс, но смена выходного IP без определённого пояса сбрасывает
устаревшее значение.
На карточке видны привязки аккаунтов и API-источников. Для удаления прокси
аккаунтов потребуется подтверждение: они перейдут на общий прокси,
а без него — на прямое подключение, если оно разрешено настройками.
Прокси API-источника сначала смените в настройках источника. Для общего прокси
выберите **Сбросить общий прокси** на этой вкладке и подтвердите сброс перед
удалением записи. Прокси из списка и явные привязки аккаунтов остаются.
Следующие запросы с унаследованным маршрутом пойдут напрямую, только если это
разрешено политикой пула; иначе они останутся недоступны.

### API-источники

1. Откройте **Подключения → Источники API → Добавить источник**.
2. Выберите сервис или **Свой API**, задайте имя, адрес и ключ провайдера.
   **Получить API-ключ** открывает кабинет выбранного сервиса.
3. Сохраните источник и проверьте найденные модели. Если каталог не загрузился,
   проверьте адрес, ключ и ошибку на карточке.
4. Добавьте источник в **Пул** либо нажмите **Запустить** для прямого подключения.

Готовая настройка подставляет адрес и формат запросов; она не выдаёт ключ
и не гарантирует доступ ко всем моделям. Для **Свой API** используйте адрес
и формат, которые указал ваш провайдер.

Для прямого запуска ChatGPT нужен API формата Responses. Если прямой запуск
недоступен из-за формата API, добавьте источник в пул и подключите приложение
через него, если пул поддерживает нужное преобразование.

**Moonshot / Kimi API** и **Kimi Code** — разные подключения. Выбирайте настройку
под свой ключ и регион кабинета. Квота Kimi Code, баланс и квота MiniMax M Plan
сейчас не считываются в Relay; проверяйте их у провайдера. Остальные поддерживаемые
сервисы перечислены в окне добавления.

### Автоматизации

В **Подключения → Автоматизации → Добавить автоматизацию** выберите действие,
аккаунты пула и, если требуется, модель. Доступны запуск отсчёта после
восстановления основной квоты и сброс при исчерпании недельной квоты.
Сохраните правило и включите его переключателем; результат появится на карточке.
Если выбранная модель перестала быть доступной аккаунтам, отредактируйте
правило и выберите другую. Relay сохраняет ваш выбор без автоматической замены.

Отсчёт запускается запросом и может расходовать квоту. Сброс возможен только
при наличии соответствующей возможности у провайдера. Автоматизация не добавляет
лимиты подписки. Задания выполняются, пока работает Relay.
Ручной кнопки запуска правила нет.

### Восстановление старых аккаунтов

Старый настольный режим своего сервера удалён. Сохранённый выбор открывает
**На устройстве**, не подключая новый Hosted и не удаляя серверные реквизиты
или выключенные локальные копии аккаунтов. Перед действием **Восстановить локальный
аккаунт** остановите его использование на старом сервере. Relay не подключается
к нему; восстановленный аккаунт остаётся выключенным и вне пула до вашего решения.
Новый режим **На сервере** — отдельный сервис в разработке. Чтобы раздать пул
этого компьютера, включите **Доступ → Локальный API → Доступ по локальной сети**.

## 3. Пул

### Участники и выбор маршрута

В **Участниках** находятся SIWC с разрешением на использование плана, допустимые BPS-подключения
и API-источники, добавленные в пул. В **Подключениях** нажмите **Добавить в пул**
на карточке аккаунта или используйте массовое действие: добавление происходит
сразу, без предупреждения о типе аккаунта.
Карточки показывают, кто в ротации, кто ожидает квоту, отключён или недоступен.
**Следующий кандидат** — предварительный выбор, а не обещание следующего запроса.

### Ротация пула

<!-- relay:topic:pool-rotation -->

Карточки идут по текущему предпочтению планировщика слева направо, затем вниз,
без подсветки. Сначала готовые кандидаты, затем ожидающие, недоступные
и отключённые; ожидание с таймером — по сроку повтора. Если модели или протоколы
дают разный выбор, оставшиеся карточки идут по свежей ограничивающей квоте
и доступным кредитам в автоматическом режиме, иначе — по сохранённому порядку.
Баланс API не задаёт приоритет. Это не очередь будущих запросов: модель, нагрузка
и привязка сессии влияют на выбор. Просмотр не сдвигает ротацию и не переносит
уже выполняющиеся запросы.

В **Настройках ротации пула** кнопка **Как работает ротация** открывает эту помощь
без закрытия настроек. В самом окне остаются только элементы управления.

#### Режимы

- **Автоматически** — баланс нагрузки, свежей квоты или кредитов и долей
  запросов. Преимущество по квоте меньше пяти процентных пунктов не заставляет
  переключаться; при разнице от пяти пунктов меньший остаток уступает.
- **По кругу** — независимые запросы циклически идут через доступных участников
  в сохранённом порядке. **Свои доли запросов** включает распределение по весам.
- **Основной и резерв** — запросы идут первому совместимому доступному участнику;
  следующие используются, если предыдущие недоступны или заняты до лимита.

Порядок можно менять перетаскиванием или стрелками. Все режимы пропускают
неподходящие модели, недоступных участников и тех, кто достиг лимита параллельности.
Доли задают относительное число запросов, а не равный расход токенов или денег.
Продолжения с владельцем по протоколу и доступность маршрутов влияют на результат.
**Одновременных запросов**
ограничивает нагрузку на участника; **Без лимита** (значение 0) снимает только дополнительный
лимит Relay, а не ограничения провайдера. Правки сохраняются автоматически.

#### Пресеты

Три кнопки применяют готовые настройки одним нажатием:

- **Рекомендуемый** — автоматический выбор по нагрузке и доступным ресурсам.
- **Равномерно** — независимые запросы идут по кругу в сохранённом порядке.
- **Аккаунты → API** — режим «Основной и резерв» с аккаунтами перед API.
  Порядок внутри каждой группы сохраняется. Запросы через резервный API
  могут расходовать его баланс.

Пресеты задают доли 1 и лимиты 0. Смена только стратегии сохраняет доли и лимиты.
Ручные отклонения от пресета отмечаются как **Свой**.
Смена режима не перезапускает приложения или шлюз, не прерывает активные запросы,
не сбрасывает cooldown и не переносит непрозрачное продолжение на другой аккаунт.

<!-- relay:topic-end:pool-rotation -->

### Ошибки и повторные попытки

Пул может выбрать другого участника после отказа до генерации. Начатый или
неопределённый запрос не повторяется автоматически на другом аккаунте.
Продолжение разговора также может требовать исходного участника.
Поэтому несколько аккаунтов не гарантируют, что любой обрыв будет незаметен
для клиента. Ожидание можно отменить в самом клиенте.

### Модели и правила участника

Есть два уровня разрешений:

- **Правила участника пула** определяют, какие его модели можно использовать.
- **Пул → Правила моделей** управляет моделями всего пула, их порядком,
  режимами размышления, скоростью и показом в ChatGPT.

Модель должна быть разрешена на обоих уровнях и доступна у провайдера.
Разрешение в Relay не открывает недоступную модель и не пополняет квоту.
**Только через API** означает, что модель не показывается в списке ChatGPT.

Модели сгруппированы по разработчику, затем по семейству и классу; новые версии
стоят выше старых. Аккаунты и API используют общий порядок Relay.
Можно перетаскивать модели внутри группы и группы целиком.
**Сбросить порядок моделей** возвращает порядок Relay. Это не меняет порядок
участников ротации. Скорости берутся из справочника модели и доступных
подключений пула. **Быстрая** и **Сверхбыстрая** появляются, когда их поддерживают
оба; время ответа они не гарантируют. BPS использует **Обычную**.
Для текстовых моделей доступна настройка **Контекст**. **Короткий контекст**
сохраняет опубликованное короткое окно модели. Только если оно неизвестно,
используются 25% известного максимума. **Длинный контекст** использует полное
известное окно. Рядом видно число токенов; наведение показывает справочный
максимум. Неизвестный максимум не заменяется выдуманными 128k. **Свой лимит** —
от 1 024 до 2 000 000 токенов, не выше известного жёсткого максимума.
Настройки сохраняются автоматически; своё число — после короткой паузы или
сразу по Enter. Escape отменяет текущий ввод.
Relay обновляет настройку без перезапуска пула и прерывания запросов. Для
запущенного Codex значок статуса поясняет необходимость перезапуска для чтения
каталога; ошибка его обновления тоже доступна по наведению или фокусу на значке.
OpenCode может потребоваться новая сессия. Claude Desktop управляет историей
самостоятельно; Relay не обрезает её принудительно под этот лимит.

### Цены и дополнительные настройки

Цены нужны для оценки использования. Откройте **Правила участника пула → Цены**.
Под каждой моделью есть два отдельных поля:

- **Тариф** — Standard, Flex, Fast или Ultrafast.
- **Контекст** — диапазон входных токенов, для которого указаны цены. Например,
  у модели с порогом 272k будут короткий контекст **≤ 272k** и длинный **> 272k**.
  Если отдельных цен для длинного контекста нет, вместо меню показано **Общий**.

Диапазоны берутся из цен конкретной модели или ранее сохранённых ручных
настроек. Это ценовые пороги, а не максимальный контекст модели. Выбор меняет
только отображаемые поля; тариф запроса и настройки контекста приложения
остаются прежними. Статистика использует фактический тариф и число входных
токенов каждого запроса. Неизвестная цена отображается как `—`; отсутствие
цены выбранного тарифа не заменяется ценой Standard.

Relay предпочитает цену провайдера, затем справочника; ручная цена служит
запасным вариантом. Поля кэша описывают стоимость, а не включают кэширование.
**Стоимость покупки, USD** используется только для оценки окупаемости.
**Не назначать запросы** прекращает новые назначения участнику.

В меню **Пресет конфигурации** можно сохранить настройки и импортировать
их с предварительным просмотром изменений. Пресет содержит правила пула,
моделей и цен; аккаунты, ключи, квота и история запросов в него не входят.

## 4. Доступ

Здесь настраивают вход в пул и поведение подключённых приложений:
**Локальный API**,
**Приложения** и **Аккаунты**.

### Локальный API

1. Запустите API и скопируйте **Адрес API**.
2. Нажмите **Копировать ключ** и вставьте его в поле API key клиента.
3. Выберите поддерживаемый формат запросов и точный ID включённой модели.
4. Отправьте запрос и проверьте его в **Использовании**.

Обычный базовый адрес для совместимого с OpenAI клиента:

```text
http://127.0.0.1:14998/v1
```

**На устройстве** — место запуска пула, а не ограничение доступа.
Берите адрес из приложения: порт может отличаться.
`127.0.0.1` работает только на этом ПК. Для другого ПК или телефона
включите **Доступ по локальной сети** и скопируйте **Адрес API в сети**
и **Сетевой API-ключ**. API нужно запустить отдельно.
Локальные профили и ключи сохраняются, в том числе при перевыпуске сетевого ключа.
Выключение переключателя закрывает доступ по сети.
Используйте доверенную частную сеть IPv4: HTTP не шифруется.
Разрешайте порт только в частном профиле брандмауэра, не в интернете.
Запросы из браузера и управление аккаунтами заблокированы.
Не добавляйте `/v1` дважды.

**Какой ключ куда вставлять**

| Ключ | Где используется |
| --- | --- |
| Ключ провайдера | В API-источнике в **Подключениях**. |
| Ключ запросов Relay | В приложении, которое подключаете к пулу. |

**Перевыпустить API-ключ** находится в меню рядом с ключом. После подтверждения
старый ключ перестаёт работать; новый скопируется в буфер. Обновите его в клиентах,
где указывали вручную. Если меняете порт, нажмите кнопку сохранения рядом:
работающий API перезапустится, а адрес клиента потребуется обновить.

**Ожидать восстановления маршрута** может удерживать подходящие текстовые
запросы, пока участник снова станет доступен. Клиент может отменить ожидание.
Настройка не исправляет неверный ключ, формат или уже начатый ответ.

**Пути для ручной настройки**

| Формат | Путь от корня сервера |
| --- | --- |
| Каталог моделей | `/v1/models` |
| Responses | `/v1/responses` |
| Chat Completions | `/v1/chat/completions` |
| Anthropic Messages | `/v1/messages` |
| Gemini | `/v1beta/models/{model}:generateContent` |

Для потокового Gemini: `/v1beta/models/{model}:streamGenerateContent?alt=sse`.
Для этого формата нужен корень сервера без окончания `/v1`.
Доступность инструментов, изображений и других функций зависит от участника
и формата. Неподдерживаемые преобразования завершаются ошибкой.
Realtime и преобразование аудио/видео не предоставляются.

### Приложения

В **Доступ → Приложения** идут ChatGPT, Claude Desktop, затем OpenCode.
Вверху настроек каждого приложения находится **Путь приложения**. Нажмите
кнопку с папкой, укажите установленное приложение и нажмите **Сохранить**.
Можно вставить абсолютный путь вручную. На macOS выбирайте пакет `.app`,
на Windows — файл `.exe`, не ярлык и не терминальный CLI. Не указывайте
аргументы команды или папку профилей и настроек.

Чтобы убрать сохранённый путь, очистите поле и нажмите **Сохранить** — Relay
вернётся к автоматическому поиску. Сохранение не запускает, не закрывает и
не подключает приложение: путь используется при следующем действии запуска.
Если файл удалён, выберите новую установку или очистите путь. Пути хранятся
в папке данных Relay на этом компьютере;
на сервер и в пресеты пула они не передаются.

Приоритет запуска: сохранённый путь, `OPENCODE_BIN` / `CLAUDE_DESKTOP_BIN`,
автопоиск. Неверный путь нужно исправить или убрать: Relay не подменяет его другой
установкой. OpenCode и Claude подтверждают запуск по процессу приложения.
Таймаут сохраняет настройки: проверьте установку и повторите запуск.

#### ChatGPT

В **Доступ → Приложения → ChatGPT** поле **Аккаунт ChatGPT** выбирает вход
для интерфейса приложения. Можно выбрать аккаунт, **Автоматически** или
**Без аккаунта**. Нажмите **Переключить**, чтобы применить выбор и перезапустить
приложение. Это не закрепляет все запросы за выбранным аккаунтом:
генерацию через API продолжает распределять пул.

**Резерв 1%** предназначен для сохранения остатка выбранного аккаунта
для прямого запуска ChatGPT.

Контекст настраивается в **Пул → Правила моделей**; см. [правила моделей](#модели-и-правила-участника).
Relay обновляет каталог без перезапуска пула, но открытый ChatGPT нужно
перезапустить, чтобы он перечитал каталог. Изменение скорости этого не требует.
Автосжатие использует около 90% выбранного окна с учётом известных лимитов
входа и ответа; отдельного переключателя нет. Контекст не выбирает тариф:
большой фактический запрос может стоить дороже.

Для **SIWC** Relay выполняет сжатие как текстовую сводку на том же подключении,
без каталога инструментов. Полученный checkpoint Relay разворачивает в сводку
при продолжении; чужие зашифрованные checkpoints не поддерживаются.

**Фоновые задачи ChatGPT** разрешают автоматические сводки активности
и названия задач. **Извлечение памяти** обрабатывает предыдущие чаты
(`memories.extract_model`), а **Сводки памяти** объединяют извлечённое в
долговременную память (`memories.consolidation_model`). В каждой строке — своя
модель и переключатель разрешения. Выберите модель из локального пула или
**По умолчанию в приложении**, чтобы убрать переопределение этого этапа.
Сначала подключите ChatGPT к локальному пулу; после смены модели перезапустите
приложение вручную. Модель основного чата не меняется.

Переключатели сразу разрешают или блокируют новые запросы соответствующего
этапа через Relay, но не включают функцию памяти в самом Codex, не удаляют
сохранённую память и не прерывают уже начатую работу. По умолчанию оба этапа
разрешены; они независимы от сводок активности и названий задач. В использовании
блокировка показана как локальное ограничение, а не лимит аккаунта. Это политика
Relay, а не штатный переключатель этапа Codex: клиент должен явно передавать
тип операции, иначе надёжная блокировка невозможна. Чтение существующей памяти
и сжатие контекста основного чата сохраняются. Модели с меньшим контекстом или
без необходимых возможностей могут не выполнить задачу памяти; наличие модели
в пуле не гарантирует результат в приложении.

**WebSocket для ChatGPT** управляет ChatGPT → Relay, не провайдером.
Изменение требует подтверждения перезапуска. В запросе — **Транспорт приложения**;
BPS и преобразования используют HTTP до провайдера.

#### Claude Desktop

В режиме **На устройстве** запустите API и выберите **Пул → Подключить → Claude Desktop**.
Relay проверит подключение, закроет Desktop и запишет собственный профиль,
сохранив остальные. Повторный запуск зависит от настройки автозапуска.
Для явного запуска выберите **Обзор → Запустить приложение → Claude Desktop**.
Корпоративная политика inference может перекрывать локальный профиль.

Список сохраняет названия и порядок пула: одна запись на включённую модель
с Messages-маршрутом, не более 200 моделей. Превышение отклоняется до изменения
профилей. Claude-совместимые ID ведут к настоящей модели. Размышление ограничено
максимальным разрешённым уровнем; пропуск заменяется ближайшим меньшим, а при
его отсутствии — минимальным разрешённым. Для Low/High/Max выбор Medium означает
Low, XHigh — High. Выключенные размышления не включаются. Правило действует только
для внутренних маршрутов выбора Desktop; **Использование** показывает оба уровня.

После обновления Relay подключите Desktop повторно и начните новый чат.
**MCP tools** и **System tools** — определения, не память или счёт: не удаляйте
рабочие инструменты, навыки и историю. Relay включает MCP-схемы по требованию;
нативному Messages по-прежнему нужна поддержка поиска у провайдера.

Кеш и стоимость определяет настоящий провайдер. Возможности без совместимого
преобразования завершаются ошибкой. `Claude-3p/configLibrary` — папка профилей,
не путь запуска. Не передавайте профиль Relay другим: он содержит ключ пула.

Для отмены подключения используйте [Восстановление](#6-восстановление).
Новые ручные выборы и изменённые профили сохраняются. При потере записи
восстановления можно повторно подключить точно совпадающий профиль Relay,
но неизвестный прежний выбор вернуть нельзя — он останется не задан.

#### OpenCode

Подключение работает через **Пул → Подключить → OpenCode** или **Запустить**
у отдельного API-источника. Раздел дополнительных настроек OpenCode в
**Доступе** пока показывает **В разработке**. Это не мешает подключить клиент.
Вернуть сохранённую конфигурацию можно в **Восстановлении**.

### Аккаунты

Здесь настраивают запросы через аккаунты. Для входа и управления сохранёнными
аккаунтами откройте **Подключения**.

**Отклонять подмену модели** проверяет имя модели в ответе аккаунта.
Если вместо запрошенной модели указана другая или внутренний id понижения,
например `degrade2`, Relay отклоняет ответ. Датированная версия той же модели
допускается. Переключатель не меняет способ входа и не проверяет качество текста.

## 5. Использование

Здесь видны запросы локального пула. Для проверки:

**Последние 24 часа** отсчитываются от текущего момента, а не от полуночи.

1. Выберите период, статус, модель или **Участника пула**.
2. В **Запросах** откройте нужную запись. Сверху показаны модель, подключение,
   дата запроса, итоговый статус и доступные показатели времени, скорости и стоимости.
   Ниже видны протокол, транспорт, скорость запроса и размышление.
3. При ошибке сразу видны её причина, HTTP-код и сохранённое сообщение
   провайдера. Кнопка рядом с сообщением копирует его.
   Во вкладке **Ошибки** собраны только неуспешные запросы.

**Токены** сразу показывают входные и выходные значения с разбивкой кэша и
рассуждений. **Инструменты** показывают сохранённые счётчики и тип вывода.
В **Технических деталях** находятся ID для копирования, выбор маршрута
и исходные коды ошибок. Если сведения сохранены, отдельно показаны запрошенная
модель, модель, отправленная источнику, и модель, заявленная в его исходном ответе.
Последнее значение — заявление источника, а не независимое подтверждение модели;
в старых записях его нет.
В маршруте также видны **Приложение → провайдер**, режим выполнения и причина
использования HTTP-моста. Формат ответа определяется по ответу провайдера.
Время подключения WS не равно задержке первого токена; при повторном использовании
сокета или отсутствии измерения его нет. Старые записи не содержат этих сведений.

Дополнительная защита native HTTP по умолчанию выключена. Например, запуск Relay
с `ZENITH_RELAY_HTTP_HEADERS_TIMEOUT_SECONDS=60` ограничивает подключение, загрузку
и ожидание заголовков общим сроком для попыток одного запроса. Допустимы 1–1800
секунд; отсутствие, ноль и неверное значение выключают защиту. Это не отдельный
таймер загрузки: в ожидание может входить очередь провайдера. После заголовков
ограничение снято, длинный ответ не обрывается; BPS и native WS оно не затрагивает.
Код `http_headers_timeout` (504, источник Relay) означает истечение этого срока.
Запрос уже мог выполняться: Relay не повторяет его автоматически и не отключает
аккаунт. Перед ручной отправкой проверьте результат в клиенте; для медленного
источника увеличьте срок или выключите эту дополнительную защиту.

**Другие фильтры** добавляют протокол, транспорт, категорию ошибки и ID запроса.
**Сбросить** в этой панели сбрасывает только дополнительные фильтры.
Если журнала нет, проверьте режим, период и адрес в клиенте: прямой запуск
аккаунта или API-источника обходит пул.

`≈` перед стоимостью означает оценку по API-ценам, `—` — недостаточно данных.
Токены измеряют объём данных для модели: входные передаются ей,
выходные создаются в ответе.
Токены кэша уже входят во входные, а токены размышления — в выходные.
Не прибавляйте их к общему числу повторно.
Тексты запросов, ответов и секреты не сохраняются в журнале использования.

**Прочитано из кэша** и **Записано в кэш** относятся к этому запросу, а не к
объёму кэша, который ещё хранит провайдер. Сообщённый ноль остаётся нулём;
`—` означает, что провайдер не сообщил счётчик. Повторное использование
префикса не требует его повторной записи. **Хранение кэша (оценка)** показано
отдельно: в локальной истории — по последнему наблюдаемому чтению/записи для
того же чата, подключения и модели провайдера; в других отчётах — по выбранному
запросу. Промах не сдвигает это наблюдение.
TTL не угадывается по имени GPT и не переносится из публичного API на BPS
или совместимый сервис. Неизвестный срок остаётся неизвестным; разные сроки
относятся к отдельным префиксам, а не к одному кэшу с максимальным TTL.
Истечение оценки не доказывает удаление кэша.

Даже приветствие передаётся вместе с инструкциями клиента, историей и схемами
инструментов. **Технические детали → Контекст** сравнивают размеры исходного и
подготовленного JSON в байтах, не токенах. BPS может добавить невидимый Relay
контекст. Кэш не освобождает окно контекста. Используйте загрузку инструментов
по требованию, если она поддерживается: каталог BPS сохраняет все инструменты
и ограничения схем без передачи всех полных описаний сразу. Параметры каталога
описаны в [контракте BPS](../../project/PLANNING.md#excel--basis-points).

Текст SSE может передаваться и при поиске инструментов; у буферизованных ответов
нет времени первого/последнего токена. Отладочное сравнение контекста не содержит
переписку и не доказывает причину промаха кэша. Расход поиска виден отдельными попытками.

У каждого ID запроса Relay одна запись и итог. **Ход запроса** показывает попытки,
ошибки провайдера и сохранённую причину остановки независимо от фильтров отчёта.
Отсутствие истории отмечается; срок её хранения совпадает с журналом запросов.

## 6. Восстановление

Этот раздел возвращает настройки установленного клиента. Он доступен в режиме
**На устройстве** и не восстанавливает квоту, удалённые аккаунты Relay или переписку.

1. Выберите **ChatGPT** или **OpenCode**.
2. Перед изменениями введите **Название снимка** и нажмите **Создать снимок**.
3. Для возврата выберите снимок, нажмите **Восстановить** и проверьте подтверждение.
   У ChatGPT сохранённые конфигурация и вход заменят текущий профиль.

У ChatGPT можно хранить несколько именованных снимков. У OpenCode хранится
один снимок до восстановления; после восстановления он расходуется.

Для Claude Desktop откройте его вкладку. Перед подключением введите
**Название снимка** и нажмите **Создать снимок** — сохраняется одна исходная
точка восстановления. Для возврата выберите снимок, нажмите **Восстановить** и
подтвердите. Локальный API может быть остановлен. Для подключённого профиля Relay
проверяет файлы, закрывает Desktop и возвращает выбор без повторного запуска.
Возврат снимка, созданного до подключения, не закрывает Desktop и не меняет его
файлы. Чужие профили и более новый ручной выбор сохранятся.

Автоматическая защищённая копия перед переключением ChatGPT создаётся отдельно
от именованных снимков. Автоматический возврат не перезаписывает более новый
ручной вход. Если Relay сообщает о конфликте, проверьте текущий профиль
перед повторной попыткой.

## 7. Настройки

**Внешний вид** меняет язык и тему. В **Приложении** показаны версия и папка
рабочих данных. Язык, тема и режим работы сохраняются сразу.
У полей с отдельной кнопкой сохранения, например порта API, используйте её.

**Запускать приложения после подключения** включено по умолчанию. Отключите эту
настройку, если нужно подключить ChatGPT, Claude Desktop или OpenCode к пулу без открытия
приложения. Выбор сохраняется сразу и после перезапуска Relay. Если вы уже
отключали запуск в прежней версии, он останется выключенным. Кнопка
**Запустить приложение** на обзоре и прямой запуск по-прежнему открывают выбранное
приложение.

**Обзор** открывает приложение без изменения подключения, профиля, ключей,
каталога и без закрытия клиента — даже при остановленном API и пустом пуле.
Для подключения используйте **Пул → Подключить**. Внешняя смена профиля не мешает
обычному запуску. Новые ручные настройки контекста ChatGPT сохраняются при
обновлении каталога, повторном подключении и восстановлении.

**Обновления.** Нажмите **Проверить** рядом с версией или **Доступно обновление**.
Ознакомьтесь с изменениями и нажмите **Обновить**.
Проверка версии сама по себе не устанавливает обновление.
Папка portable-версии Windows должна быть доступна для записи.

**Диагностика.** В режиме **На устройстве** включите **Данные пула → Режим отладки**,
чтобы появился раздел **Диагностика** с папками журналов. Ошибки и падения
записываются и без отладки; подробные операции — при её включении.

**Сбросить данные локального пула** удаляет аккаунты, источники, настройки
и статистику после безопасного возврата настроек клиента. Если возврат
невозможен, удаление не выполняется. Для обычной ошибки подключения сначала
используйте проверки ниже; сброс не является переавторизацией.

## 8. Ошибки

### Сначала проверьте

| Что происходит | Что сделать |
| --- | --- |
| Аккаунт сохранён, но его нет в выборе участников | Для пула нужны SIWC с разрешением на использование плана или допустимый BPS. Codex предназначен для переключения аккаунтов и справочной квоты SIWC. Free BPS и уже добавленные участники не показываются. |
| **Подключить** недоступно | Запустите **Доступ → Локальный API** и проверьте доступных участников пула. |
| API работает, но моделей нет | Проверьте участников, доступ провайдера и разрешения модели у участника и в **Правилах моделей**. Сам запуск API не добавляет модели. |
| Клиент не соединяется | Проверьте адрес, порт и ключ запросов Relay. Адрес `127.0.0.1` работает только на том же компьютере. |
| Запроса нет в **Использовании** | Сбросьте фильтры и проверьте режим. Прямой запуск аккаунта или источника не проходит через пул. |
| Все участники ожидают квоту | Дождитесь сброса у провайдера или добавьте другое доступное подключение. **Обновить** только перечитывает квоту. |
| После изменения контекста всё осталось прежним | Закройте и снова запустите ChatGPT. Проверьте, что используете управляемое Relay подключение. |

Если это не помогло, найдите код или текст ошибки в справочнике ниже.

Откройте ошибку карточки или запрос в **Использовании**. Смотрите вместе
**Источник ошибки**, категорию Relay, код провайдера и HTTP-статус.
Например, `invalid_api_key` может относиться к ключу самого пула или к ключу
внешнего API. Исправлять нужно подключение, указанное в деталях.

Если в деталях есть ID запроса провайдера, скопируйте его для обращения в его
поддержку. Это ID на стороне провайдера; локальный ID Relay отображается отдельно.
Relay также добавляет поддерживаемый ID провайдера в текст ошибки для клиента,
чтобы он был виден и в чатах, которые показывают только сообщение.

Ниже перечислены коды Relay и распознаваемые им ситуации. Произвольное
сообщение внешнего провайдера может отличаться; для него сохранены очищенные
детали. `exceeded retry limit` означает, что клиент исчерпал повторы:
причину показывает последняя ошибка, например 429. Увеличение повторов
не восстанавливает квоту.

| --- | --- | --- |
| `admission_queue_full` | Достигнут лимит ожидающих запросов или удерживаемых данных для пула либо ключа. Новый запрос провайдеру не отправлен. | Уменьшите число одновременных ожиданий или размер входных данных, дождитесь освобождения очереди и повторите запрос. |

| Код или сообщение | Причина | Что сделать |

Следуйте подсказке аккаунта и войдите снова, если обновление больше невозможно. Ключ пула менять не нужно при ошибке авторизации провайдера. |

| `upstream_region_unsupported`, `unsupported_country_region_territory` | Провайдер не обслуживает регион подключения. | Проверьте поддерживаемые регионы и разрешённую конфигурацию сети у провайдера. Используйте доступное в вашем регионе подключение. |

До генерации возможен переход к другому участнику; сгенерированный или переданный ответ не повторяется. Датированная версия той же модели допускается. Аккаунт ненадолго встаёт на паузу. | `upstream_model_capacity`, `model_at_capacity` | Модель временно перегружена. | Дождитесь паузы или используйте другой совместимый источник. Переавторизация не увеличивает мощность провайдера. |

### Запрос, история и инструменты

| Код или сообщение | Причина | Что сделать |
| --- | --- | --- |
| `invalid_request`, `upstream_invalid_request` · 400 / 422 | Неверное тело или параметры запроса. | По очищенному сообщению исправьте поле в клиенте. Нужны JSON-объект, непустая модель и корректный `stream`; модель в пути должна совпадать с телом. Compact-ответы не поддерживают поток. |
| `invalid_stream_id` · 400 | Неверный `stream_id` в Responses WebSocket. | Укажите 1–256 латинских букв, цифр, `_`, `-` или `.`; для потока по умолчанию уберите поле. |
| `upstream_context_too_large`, `context_too_large`, `context_length_exceeded` | История превышает контекст модели. | Сократите историю и вложения, сделайте сводку или начните новый разговор. При необходимости выберите модель с большим контекстом. |
| `request_too_large`, `upstream_payload_too_large` · 413 | Провайдер отклонил слишком большой запрос. | Сократите историю или удалите часть изображений. Relay не отклоняет JSON-генерацию, загрузку и редактирование изображения из-за размера. Повтор неизменённого запроса не поможет. |
| `request_encoding_unsupported` · 415 | Неподдерживаемое или многослойное сжатие запроса. | Отправляйте обычный JSON либо используйте один формат `gzip` / `zstd`. |
| `request_encoding_invalid` · 400 | Сжатое тело повреждено, оборвано или требует окна распаковки zstd больше 64 МиБ. | Обновите клиент либо отключите сжатие запросов. На размер сжатого и распакованного JSON Relay лимит не ставит. |
| `compaction_response_invalid` · 502 | Сжатие контекста не завершилось корректным зашифрованным результатом. | Сохраните историю разговора и повторите действие вручную после проверки соединения с провайдером. Relay не повторяет эту генерацию автоматически и не выдумывает краткое содержание. |
| `upstream_instructions_required`, `missing_required_parameter` | Отсутствует обязательное поле, в том числе инструкции. | Добавьте поле, указанное провайдером; обновите клиент, если он формирует запрос сам. Обычный повтор без изменения тела не поможет. |
| `upstream_unsupported_request`, `unsupported_request` | Провайдер не поддерживает параметр или возможность. | Отключите неподдерживаемый параметр, инструмент или режим и используйте совместимый формат. |
| `upstream_content_policy`, `content_policy_violation` | Запрос отклонён политикой провайдера, в том числе This request was blocked by our usage policy. | Настоящий HTTP 403 сохраняется, даже если посредник назвал его insufficient_quota. Relay не обнуляет квоту, не ставит аккаунт на паузу и не перебирает участников из-за этого отказа. Проверьте правила провайдера и доступ к маршруту; заголовки не дают разрешения на доступ. |
| `response_continuation_unavailable`, `response_affinity_miss` | Владелец ответа недоступен либо обязательный контекст продолжения потерян/изменён. | Верните исходный аккаунт или API либо отправьте полную историю, допускающую перенос. Токен продолжения Gemini требует того же локального ключа, модели и исходных contents: его нельзя перенести к другому владельцу. Если состояние потеряно, начните новый разговор. Смена режима ротации не восстанавливает контекст. |
| `upstream_previous_response_not_found`, `previous_response_not_found` | Провайдер больше не знает предыдущий ответ. | Повторите из клиента с полной историей без устаревшей ссылки на ответ. Если это невозможно, начните новый разговор; не переносите один ID на другой API. |
| `upstream_tool_call_mismatch`, `tool_call_not_found` | Результат инструмента не связан с исходным вызовом или отсутствует ответ на вызов. | Relay повторяет запрос один раз, если полная пара позволяет однозначно восстановить отсутствующий или перепутанный идентификатор. Результаты не удаляются, параллельные вызовы не связываются наугад. Если ошибка осталась, обновите клиент и повторите шаг с полной парой «вызов + результат». Если утраченную историю восстановить нельзя, начните новый разговор. |
| `upstream_encrypted_content_invalid`, `invalid_encrypted_content` | Аккаунт не принял зашифрованный контекст рассуждений или сжатия. | Если зашифрованы только рассуждения, Relay может убрать отклонённый шифротекст и связанный ID, сохранить видимые сводки и повторить запрос один раз до вывода ответа. Зашифрованный checkpoint сжатия запрещает такое восстановление: история остаётся целой, Relay возвращает ошибку. Вернитесь к подключению, создавшему элемент, либо начните новую задачу с обычной историей. Не редактируйте зашифрованные блоки вручную. |
| `tool_use_not_supported`, `chat_feature_not_supported` | Этот маршрут не может представить запрошенный инструмент или функцию. | Совместимые маршруты Chat Completions поддерживают вызовы функций и их результаты. Проверьте возможности формата модели, выберите подходящий нативный маршрут или уберите конкретный неподдерживаемый параметр. |
| `upstream_conflict`, `conflict` · 409 | Состояние изменилось либо операция конфликтует с уже выполняемой. | Дождитесь предыдущей операции, обновите состояние и повторите один раз. Если сообщение относится к продолжению, восстановите его историю. |
| `upstream_candidate_rejected`, `source_rejected` | Выбранный маршрут отклонил запрос без более точной категории. | Посмотрите код и сообщение провайдера. Проверьте модель, права и формат; для нового независимого запроса можно использовать совместимый резерв. |

### Если код не найден

Внешние провайдеры могут добавлять свои коды. Откройте детали запроса:
сохранённый код и сообщение провайдера точнее общего HTTP-статуса.
Если после начала ответа произошёл обрыв, Relay не смешивает частичный ответ
с новым ответом другого участника. Для продолжения может понадобиться
полная история или исходное подключение.

Для обращения за помощью укажите версию Relay, режим работы, действие,
модель, HTTP-статус, источник ошибки, код и ID запроса. Очищенные детали
и журналы доступны в **Использовании** и **Настройках → Диагностика**.
Не отправляйте ключи, cookies, файлы входа, экспорты аккаунтов или разговоры.
