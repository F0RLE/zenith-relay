# Zenith Relay

Relay подключает ChatGPT, OpenCode и совместимые клиенты к сохранённым
аккаунтам и API-источникам. Пул выбирает доступное подключение для каждого
запроса и предоставляет один приватный API-адрес.

## Как работает Relay

- **Подключения** хранит аккаунты, API-источники, ключи и прокси.
- **Пул** определяет, какие подключения и модели могут принимать запросы.
- **Интеграции** разделяет настройку приложений и аккаунтов.
- **API** показывает адрес и ключ запросов для клиентов.

Сохранение подключения, добавление его в пул и подключение клиента — разные
действия. Подключение можно сохранить, но не использовать в пуле.

### Режимы работы

- **Компьютер:** локальный процесс Relay запускает пул и API.
- **Выбор API:** клиент работает с одним выбранным API напрямую; ротация пула
  и его история использования не применяются.
- **На своём сервере:** пул работает на управляемом пользователем Relay Server,
  а настольное приложение управляет им. Закрытие приложения сервер не останавливает.

Смена режима не переносит аккаунты и секреты. Перенос аккаунта на свой сервер
выполняется отдельно и требует подтверждения.

### Быстрый старт

1. Выберите **Компьютер** или **На своём сервере**.
2. В **Подключениях** войдите в ChatGPT, импортируйте аккаунт или добавьте
   API-источник.
3. В **Пуле** добавьте подключения и разрешите нужные модели.
4. Запустите **API**, затем откройте **Пул → Подключить** для ChatGPT или
   OpenCode. Для других клиентов используйте адрес и ключ из **API**.
5. Отправьте запрос и проверьте **Обзор** или **Использование**.

**Повторить быструю настройку** в **Помощи** снова открывает мастер. Для
прямого подключения к одному источнику используйте **Выбор API** или действие
**Запустить** у API-источника.

### Установка на macOS

Переместите приложение из DMG в **Программы**. Сборка подписана ad-hoc и не
нотариально заверена. Если macOS блокирует первый запуск, выберите
**Системные настройки → Конфиденциальность и безопасность → Открыть всё равно**
для этого приложения. Не отключайте Gatekeeper для всей системы.

Если контрольная сумма релиза совпадает, но macOS сообщает о повреждении,
снимите карантин только с приложения:

~~~sh
xattr -dr com.apple.quarantine "/Applications/Zenith Relay.app"
~~~

## 1. Обзор

**Обзор** показывает выбранный режим, адрес, доступные модели, участников
пула, число запросов и скорость. Период и область статистики выбираются отдельно.

### Балансы и оценки

Провайдер может отдавать баланс, остаток ключа или остаток подписки. Relay
хранит эти значения раздельно и сохраняет валюту или единицы провайдера.
**Нет API баланса** означает, что подходящий способ проверки не найден;
**Доступ к статистике запрещён** означает отказ провайдера. Запросы при этом
могут работать.

Используйте **Обновить баланс**, чтобы запросить новое значение. После ошибки
старое значение сохраняется и помечается устаревшим. Перезапуск очищает
временный кэш статистики. Оценка Relay и **Эквивалент API использован** — это
оценка использования, а не баланс и не подтверждённое списание провайдера.

## 2. Подключения

### Аккаунты и квота

Добавьте аккаунт ChatGPT через окно входа или импортируйте свой файл. Заметки
аккаунта можно менять; учётные данные и экспорт — секретные данные.
**Обновить** читает состояние аккаунта, модели и квоту у провайдера. Команда не
добавляет квоту и не придумывает дату сброса. Отозванный вход нужно пройти снова.

Сохранённое подключение не обязано быть участником пула. Отключённый или
недоступный аккаунт можно оставить для восстановления. Обновления используют
настроенный прокси и не перезаписывают новые учётные данные старым запросом.

### Вход в аккаунт

В окне **Войти** выберите способ подключения:

- **ChatGPT** — нативный вход ChatGPT. Подходит для прямого запуска аккаунта
  и работы через пул.
- **Excel / Basis Points** — отдельный вход через OAuth-клиент Excel. Работает через
  пул Relay; после тарифа отображается метка **BPS**.

Один ChatGPT-аккаунт можно сохранить обоими способами: это разные подключения.
Метка **BPS** обозначает вход **Excel / Basis Points**. Это один способ входа,
названный по клиенту Excel и его маршруту Basis Points. Общий остаток кредитов
одного аккаунта считается один раз для обоих входов. Ошибки входа и доступность
каждого подключения отображаются отдельно.

Нажмите **Открыть окно входа** и завершите вход в окне Relay. Возврат
принимается автоматически. Для ChatGPT кнопка копирования справа от
**Открыть окно входа** позволяет войти в браузере на этом же компьютере.
Выбор другого способа начинает новую попытку в том же диалоге.
При повторном входе способ зафиксирован, нужен тот же аккаунт; заметки
сохраняются и сами в форму входа не подставляются.

Кнопка с замком рядом с **Открыть окно входа** выбирает сохранённый HTTP-прокси
для окна входа, обмена токена и нового подключения. ПКМ повторяет последний
выбор. Крестик или Escape закрывают окно; в окне входа это отменяет текущую
попытку. Во время подготовки и сохранения аккаунта закрытие заблокировано.

**Как подключить Excel / Basis Points к клиенту**

1. После входа добавьте подключение **BPS** в **Пул → Участники** и разрешите
   нужные модели.
2. Запустите **API**.
3. Для ChatGPT откройте **Пул → Подключить → ChatGPT**; для OpenCode —
   **Пул → Подключить → OpenCode**. Другие совместимые клиенты используют
   адрес и ключ запросов из **API**.
4. Выберите модель с обычной скоростью и отправьте запрос. Наличие модели
   в списке аккаунта само по себе не подтверждает доступ к ней через BPS.

**Возможности и ограничения**

- Поддерживаются текст, function/custom-инструменты и изображения,
  переданные внутри запроса. Удалённые URL изображений, структурированный
  вывод и продолжение только по `previous_response_id` не поддерживаются.
- Для входа BPS доступны запросы с обычной скоростью. **Быстрая** и
  **Сверхбыстрая** недоступны; поток может начать выдаваться после готового
  ответа провайдера.
- Прямое действие **Запустить** для ChatGPT, нативная генерация изображений
  и **Agent Identity** недоступны. Экспорт — только **Zenith** или **Sub2API**.
- BPS не гарантирует отсутствие деградации. Отказ провайдера смотрите
  в **Использовании**; повторный вход нужен при ошибке учётных данных.

**Маршрут и добавление в пул**

Обычный вход **ChatGPT** всегда использует нативный маршрут. Basis Points
доступен только для отдельного входа **Excel / Basis Points**. Старый
переключатель и импорт старых настроек способ входа не меняют.

При добавлении обычного аккаунта в пул Relay предупреждает о возможных
ограничениях, блокировке или снижении качества ответов. **Продолжить**
добавляет аккаунт, **Пропустить** оставляет его вне пула. При импорте сам
аккаунт сохраняется. В смешанном выборе BPS и API-источники добавляются.
**Больше не напоминать** скрывает следующие предупреждения на этом устройстве;
ПКМ по кнопке добавления выполняет действие сразу.

**Отклонять подмену модели** отклоняет ответ с другой моделью или внутренним
id понижения. Настройка не меняет маршрут и не оценивает качество текста.
Ни вход BPS, ни проверка имени модели не гарантируют отсутствие деградации
или ограничений аккаунта.

Кнопка **?** в окне входа открывает этот раздел, сохраняя текущую попытку.

### Прокси

Сохраняйте прокси в **Подключения → Прокси** или импортируйте по одному адресу
в строке. **Проверить прокси** проверяет выбранный адрес и показывает результат.
Ключ аккаунта не используется, прямого обхода при ошибке нет.
Последний результат сохраняется на устройстве вместе с прокси: выходной IP,
страна, задержка, время проверки или код ошибки. После перезапуска Relay он
остаётся виден. Повторная проверка обновляет данные; сохранённый результат
не подтверждает текущую доступность.

### API-источники

В **Добавить источник** выберите известный сервис или **Свой API**. Укажите
адрес провайдера, ключ и имя. Полный endpoint может подсказать протокол. Relay
сохраняет все модели, которые вернул источник; совместимость маршрута
проверяется позже.

Готовые настройки есть для OpenAI, Anthropic, Google Gemini, DeepSeek, Groq,
Mistral, Moonshot / Kimi API, Kimi Code, MiniMax, OpenRouter и Zenith.
Кнопка **Получить API-ключ** открывает кабинет выбранного сервиса.

- **Moonshot / Kimi API** — оплата за использование. По умолчанию выбран
  международный адрес `https://api.moonshot.ai/v1`, баланс в USD. Для ключа
  китайского кабинета укажите `https://api.moonshot.cn/v1`; баланс будет в CNY.
  Ключи этих кабинетов различаются.
- **Kimi Code** — отдельная подписка и ключ из Kimi Code Console. Готовая
  настройка использует Messages endpoint
  `https://api.kimi.ai/coding/v1/messages`; для китайского входа замените
  `.ai` на `.com`. Ключ Moonshot сюда не подходит. Квота подписки в Relay
  пока не считывается; смотрите её в Kimi Code.
- **MiniMax** — готовый адрес Chat Completions. Баланс и квота M Plan в Relay
  пока не считываются.

Баланс читается отдельным запросом у поддерживаемых сервисов. Отсутствие
такого API не означает нулевой остаток и само по себе не блокирует запросы.
Расход, рассчитанный Relay, остаётся отдельной оценкой.

**Запустить** подключает клиента напрямую к источнику и обходит ротацию и
историю пула. Используйте **Пул → Подключить**, если запрос должен выбирать
Relay.

### Автоматизации

В **Подключения → Автоматизации** можно запустить отсчёт квоты или запросить
сброс у провайдера, когда выполнено условие. Выберите тип, аккаунты и модель,
если нужен запрос, затем сохраните и включите правило. Локальные задания
работают пока запущен Relay; серверные зависят от возможностей сервера.
Отдельной кнопки ручного запуска нет.

### Свой сервер

Сохраните адрес Relay Server и management token в подключении сервера. Клиенты
используют API-адрес сервера и отдельный ключ запросов. Перенос аккаунта на
сервер выполняется явно и с подтверждением; автоматической синхронизации нет.

## 3. Пул

### Участники и выбор маршрута

Добавьте сохранённые аккаунты и API-источники в **Участники**. В правилах
участника разрешите или запретите модели. Удаление участника не удаляет его
подключение. Relay проверяет модель и протокол запроса, затем пропускает
отключённые, вышедшие из входа, недоступные, заблокированные квотой или занятые
по лимиту параллельности подключения.

У пула два режима ротации:

- **Автоматически:** выбирает доступного участника по текущей нагрузке, свежей
  квоте или кредитам, весу и лимиту параллельности. Продолжение остаётся у
  владельца ответа, если нет безопасной сохранённой истории для переноса.
- **Вручную:** идёт по сохранённому порядку, пропускает недоступных или занятых
  участников и после последнего возвращается к первому.

Изменения режима, порядка, весов, лимитов и состава сохраняются в политике
пула. Подсказка следующего кандидата предварительная; перед отправкой доступ
проверяется снова.

### Ошибки и повторные попытки

Relay повторяет запрос только до появления данных ответа и когда может доказать,
что провайдер его не принял. Отправленный или неопределённый запрос нельзя
молча повторить на другом аккаунте. Ограничения провайдера и время сброса
сохраняются. Долгая генерация не прерывается только из-за паузы вывода; её
можно отменить в клиенте.

### Модели и правила участника

Правило участника разрешает модель, но не показывает квоту. **Правила моделей**
управляют разрешением для пула, порядком, режимами рассуждения и скоростью.
Модели с одинаковым отображаемым именем остаются разными ID. Неизвестные
лимиты и уровни рассуждения не угадываются; метаданные не создают маршрут,
которого нет у источника.

**Сбросить порядок моделей** возвращает порядок групп провайдеров. Внутри
группы модели ChatGPT идут по приоритету из каталога аккаунта, остальные —
в порядке ответа API-источника. При совпадении ID порядок задаёт аккаунт,
остальные модели добавляются из API. Обновите аккаунт, чтобы перечитать
приоритеты. Сохранённый вручную порядок имеет преимущество. Порядок моделей
и порядок участников ротации — разные настройки. **Стандартно**,
**Быстро** и **Ультрабыстро** — уровни обработки совместимых моделей OpenAI;
они не обещают скорость ответа.

### Цены и дополнительные настройки

Цены в правилах участника используются для оценки использования. Наблюдение
провайдера важнее справочной цены, ручная цена используется как запасной
вариант. Цена не меняет доступность маршрута и не списывает деньги с кошелька.
Поля кэша описывают цену и не включают кэширование.

**Вывод из пула** запрещает новые назначения. **Стоимость покупки, USD** нужна
только для оценки окупаемости. Пресеты переносят настройки пула и моделей, но
не ключи, входы, квоту и историю запросов.

## 4. Интеграции

**Приложения** настраивает подключение клиентов. **Аккаунты** разделяет
настройки запросов по провайдерам. Сохранённые подключения находятся
в **Подключениях**.

### Приложения

#### ChatGPT

Вкладка **ChatGPT** выбирает аккаунт для интерфейса ChatGPT. Это не тот же выбор,
что аккаунт для запроса через пул. Фоновые задачи и настройка WebSocket ChatGPT
управляют только интеграцией клиента.

Карточки моделей ChatGPT и правила Relay
обновляются отдельно; Ultra — режим оркестрации ChatGPT, а не уровень рассуждения
провайдера.

#### OpenCode

Используйте **Пул → Подключить → OpenCode** для общего пула или **Запустить** у
одного API-источника. Relay по возможности сохраняет адрес, ключ, SDK и модель.
**Восстановление** возвращает сохранённую конфигурацию OpenCode.

### Аккаунты → ChatGPT

#### Excel / Basis Points

Этот маршрут используют только входы **Excel / Basis Points**. Обычный вход
**ChatGPT** всегда использует нативный Responses, в том числе в пуле.
Переключателя для отправки обычных учётных данных через Excel нет.

Маршрут использует квоту и слот ротации подключения и может вернуть готовый
ответ до выдачи запрошенного SSE. Для него
отклоняются структурированный вывод, удалённый URL изображения и непрозрачное
продолжение `previous_response_id`. Быстрые режимы для Excel недоступны.

Excel использует обычные правила паузы и восстановления маршрута.
Явные ошибки учётных данных и аккаунта сохраняют обычное восстановление.
Отказ транспорта не обнуляет квоту и не помечает аккаунт сломанным; Relay не
перебирает аккаунты для повтора отказа доступа. Basis Points не гарантирует
качество модели или защиту от ограничений аккаунта.

#### Проверка подмены модели

**Интеграции → Аккаунты → ChatGPT → Отклонять подмену модели** сравнивает модель, указанную в ответе
аккаунта ChatGPT, с моделью, отправленной участнику. Ответ с другой моделью
или внутренним id понижения, например `degrade2`, отклоняется. Датированная
версия той же модели допускается.

Настройка действует независимо от Basis Points. Она не меняет маршрут,
не оценивает качество текста и не подтверждает, что модель работает без
деградации. Отказ до генерации может позволить выбрать другого участника;
начатый ответ не повторяется.

## 5. API

### Адрес и ключ для приложения

Вкладка **API** показывает состояние, локальный адрес, запуск и ключ запросов.
Обычный локальный адрес:

```text
http://127.0.0.1:14998/v1
```

Ключ запросов отличается от ключа провайдера и management token сервера.
**Перевыпустить ключ API** заменяет его после подтверждения. Изменение порта
перезапускает локальный API.

Поддерживаемые локальные пути:

| Формат | Путь |
| --- | --- |
| Responses | `/v1/responses` |
| Chat Completions | `/v1/chat/completions` |
| Anthropic Messages | `/v1/messages` |
| Gemini | `/v1beta/models/{model}:generateContent` |

Для Gemini поток использует `:streamGenerateContent?alt=sse`. Нативные
маршруты сохраняют параметры провайдера; неподдерживаемый формат преобразования
завершается до генерации. Realtime и преобразование аудио/видео не поддерживаются.

### Восстановление маршрута

**Ждать восстановления маршрута** может удерживать подходящие текстовые запросы,
пока пул восстанавливается. Настройка не исправляет неверный ввод и не повторяет
запрос, уже принятый провайдером.

## 6. Использование

**Использование** содержит запросы выбранного локального или серверного пула.
Прямые вызовы провайдера и активность вне Relay не входят. В запросе видны
запрошенная и отправленная модели, участник, протокол, время, токены и оценка
цены, если она доступна. Источник ошибки, код провайдера, статус и сокращённое
сообщение хранятся отдельно от текста запроса и ответа.
Над сводкой доступны период, статус, модель и участник пула. Выбор аккаунта
в **Участнике пула** открывает его квоты и оценку стоимости. В **Ошибках**
показаны только неуспешные запросы, без карточек успешности и скорости.
Фильтры протокола, транспорта, категории ошибки и ID запроса доступны
в **Запросах → Другие фильтры**, справа от выбора участника пула.
Панель открывается под верхними фильтрами; кнопка **Сбросить** внутри неё
сбрасывает только дополнительные фильтры.
Вверху сведений о запросе показаны общее время, первый вывод, скорость генерации
и оценка стоимости по API-ценам. Неизвестная стоимость обозначается `—`;
`≈` означает оценку, а не фактическое списание. Вкладка **Инструменты**
показывает количество и тип вывода; отправленное количество показано отдельно,
только если оно отличается от полученного от клиента.
Во вкладке **Токены** стоимость также показана под общим числом токенов.
Известная стоимость выделена зелёным.

В режиме отладки во вкладке **Контекст** у новых нативных Responses-запросов доступно
**Сравнение контекста**. Оно разделяет изменения параметров клиента,
отправленных параметров и изменения Relay в текущем запросе. Также видны
дополнение или переписывание истории и смена участника пула. База — предыдущий
успешно завершённый запрос той же сессии или ключа кэша; она хранится в памяти
до 30 минут и сбрасывается вместе с runtime. Пересекающиеся запросы и
продолжения с неполной историей не сравниваются как полные соседние истории.
Общий префикс считается по целым элементам `input`, а размеры — в байтах JSON,
не в токенах. Содержимое и хеши не сохраняются в журнале. Это локальная
диагностика, а не подтверждённая причина промаха кэша у провайдера. Старые записи
и другие протоколы этого раздела не имеют.

## 7. Восстановление

**Восстановление** доступно в режиме **Компьютер**. Снимок ChatGPT содержит
управляемые Relay `config.toml` и `auth.json`; снимок OpenCode — выбранную JSON
конфигурацию. Восстановление заменяет содержимое выбранного снимка. Автобэкап
перед подключением клиента отдельный и не заменяет новый вход или внешнее
изменение.

## 8. Настройки

**Внешний вид** управляет языком и темой. **Приложение** показывает версию,
обновления и папку данных. **Режим отладки** добавляет подробные журналы
операций; ошибки и сбои записываются и без него. **Сброс локальных данных пула**
сначала пытается безопасно восстановить настройки клиента и удаляет данные
только при безопасном восстановлении.

## 9. Ошибки
<!-- relay:error-reference -->

Откройте ошибку карточки или запрос в **Использовании**. Смотрите вместе
**Источник ошибки**, категорию Relay, код провайдера и HTTP-статус.
Например, `invalid_api_key` может относиться к ключу самого пула или к ключу
внешнего API. Исправлять нужно подключение, указанное в деталях.

Если в деталях есть ID запроса провайдера, скопируйте его для обращения в его
поддержку. Это ID на стороне провайдера; локальный ID Relay отображается отдельно.
Relay также добавляет поддерживаемый ID провайдера в текст ошибки для клиента,
чтобы он был виден и в чатах, которые показывают только сообщение.

Ниже перечислены коды Relay и распознаваемые им ситуации. Произвольное
сообщение внешнего провайдера может отличаться; для него сохранены очищенные
детали. `exceeded retry limit` означает, что клиент исчерпал повторы:
причину показывает последняя ошибка, например 429. Увеличение повторов
не восстанавливает квоту.

### Если код не найден

Внешние провайдеры могут добавлять свои коды. Откройте детали запроса:
сохранённый код и сообщение провайдера точнее общего HTTP-статуса.
Если после начала ответа произошёл обрыв, Relay не смешивает частичный ответ
с новым ответом другого участника. Для продолжения может понадобиться
полная история или исходное подключение.

Для обращения за помощью укажите версию Relay, режим работы, действие,
модель, HTTP-статус, источник ошибки, код и ID запроса. Очищенные детали
и журналы доступны в **Использовании** и **Настройках → Диагностика**.
Не отправляйте ключи, cookies, файлы входа, экспорты аккаунтов или разговоры.
