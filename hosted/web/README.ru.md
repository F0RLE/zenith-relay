# Relay Hosted web

[English](README.md)

Клиентский кабинет и панель владельца Hosted — **предпросмотр, а не работающий
серверный сервис**. Авторизация, серверное хранение, настоящие ключи, платежи и
интеграция API не реализованы. Их разработка и приёмка остаются в
[плане Hosted](../../docs/hosted/HOSTED_RELAY_ROADMAP.md).

У пакета React/TypeScript/Vite отдельные точка входа, зависимости и сборка.
Он использует чистые функции представления и стили Desktop из того же репозитория,
но не имеет доступа к Desktop IPC, хранилищу credentials или локальному runtime.

## Локальный запуск

Из `hosted/web/`:

```powershell
bun install --frozen-lockfile
bun run dev
```

Открыть `http://127.0.0.1:1441/`. После установки зависимостей команда
`bun run web:dev` из корня запускает тот же сервер. В development используются
учебные данные; production-сборка не включает их и имитацию авторизованных сессий.

## Кабинеты и учебные данные

| Вход | Разделы |
| --- | --- |
| `/` | Публичная страница, переход к моделям, возможности и FAQ |
| `/app/overview` | Обзор, Использование, Модели, Статус, Ключи, Баланс |
| `/admin/overview` | Обзор, Подключения, Пул, Модели, Использование, Уведомления |

Маршруты определены в `src/features/app/routes.ts`. Неизвестные разделы показывают
«Страница не найдена». Кабинет клиента отделён от панели владельца и не содержит
переключателя роли. `/preview.html?page=…` — вход в клиентский интерфейс только для
development.

Операции меняют снимок в памяти, а не на сервере. Подключения, состав пула и
экономика аккаунтов используют учебные данные. Создание подключения не добавляет
его в пул: требуется подтверждение. Восстановление из корзины не возвращает
подключение в пул и не снимает паузу. Перезагрузка сбрасывает изменения текущего
окна. Изменения каталога также могут передаваться другим открытым вкладкам
предпросмотра, как описано ниже.

Production-вход показывает отсутствие подключения или данных. `/login` и
`/admin/login` никого не авторизуют; открытие панели владельца не даёт прав.
Статический хостинг должен возвращать `index.html` для маршрутов приложения,
включая `/app/*` и `/admin/*`. Это публикация интерфейса, а не бэкенда.

## Каталог и подключения

- Изменения каталога владельца передаются открытым вкладкам через
  `BroadcastChannel`. Без него они остаются в текущей вкладке. Закрытие всех
  вкладок теряет изменения. Это не серверное хранение, авторизация или публикация
  тарифов.
- Оба кабинета используют общую проекцию каталога и порядок моделей. Перемещение
  моделей не меняет ротацию, доступность маршрутов или списания.
- Редактор API-подключений работает только с учебными данными. Он не принимает
  ключи поставщиков и не отправляет им запросы. Обновление квоты и источников
  недоступно до интеграции API. Локальные аккаунты в предпросмотр не импортируются.
- Экономика аккаунтов — оценка по API-ценам, а не списания клиентов или затраты
  поставщика. Общая квота учитывается один раз на ledger; окупаемость требует
  связанных данных использования и цены покупки. Неполные итоги приблизительны.
- Неизвестные квота, цена, баланс и использование не превращаются в ноль.
  Истёкшее окно квоты не становится полным. Запись в каталоге не доказывает
  доступность; без мониторинга история статуса остаётся нейтральной.
- `src/features/models/model.ts` задаёт представление предложений. Ставки — целые
  microUSD за миллион токенов. Уровни, диапазоны контекста и сравнения цен входят
  в серверный контракт; интерфейс не выводит их из названий моделей, предельного
  контекста или истории запросов. Отсутствующие ставки не заимствуются из другого
  уровня, длительности записи кеша учитываются отдельно.

Учебные операции и локальная арифметика проверяют согласованность представления.
Они не реализуют серверные цены, расчёты, контроль доступа или работу поставщика.

## Оформление и локализация

[DESIGN.md](DESIGN.md) описывает действующие визуальные правила и взаимодействия.
[PRODUCT.md](PRODUCT.md) определяет продуктовую область. Локальные шрифты Golos
Text и лицензия SIL OFL находятся в `public/fonts`.

Английский — основной и резервный язык; язык браузера его не переопределяет.
Русский и упрощённый китайский загружаются при выборе или восстановлении
сохранённого языка. Тема и язык могут сохраняться в localStorage; ошибка
хранилища не блокирует интерфейс. Смена языка сохраняет черновики и фильтры и
синхронизируется между вкладками. Запоздавший словарь не меняет более новый выбор.

Чтобы добавить язык:

1. Создать `src/i18n/messages/<locale>.json` с ключами английского словаря и
   совпадающими подстановками. Компоненты используют смысловые ключи
   `t("common.save")`.
2. Добавить код, название, короткую подпись, направление текста, начало недели и
   динамический импорт в `src/i18n/registry.ts`. Флаг в `LanguageFlag.tsx`
   необязателен: вместо него используется короткая подпись.
3. Запустить проверки словарей и unit-тесты; проверить длинные подписи, даты,
   мобильную компоновку, клавиатуру и направление текста перед включением языка.

Числа и даты следуют выбранному языку; сохранённые даты остаются ISO, денежная
арифметика — целыми microUSD. Идентификаторы и данные поставщиков не переводятся.
Основная документация ведётся на английском, переводы — в отдельных языковых
файлах. Выбор языка через URL пока не реализован.

## История, ключи и навигация

История запросов отделена от платежей. Фильтры и пагинация работают с загруженным
снимком, а не серверными страницами. Обзор использует скользящие интервалы до
`snapshot.asOf`; «Сегодня» в использовании начинается в полночь UTC. Пустые
интервалы графика и неизвестные списания не означают замеры или бесплатные запросы.

Кешированные токены входят во входные, токены рассуждений — в выходные.
Состояния выполнения и учёта независимы. Hosted показывает списания клиента,
а не API-эквивалент Desktop. Итоговые реальные списания должны приходить из
авторизованного Hosted API, а не рассчитываться в браузере.

Учебный ключ показывается целиком один раз и не попадает в хранилище или URL.
Создание, перевыпуск и отзыв меняют только предпросмотр; перевыпуск автоматически
не отзывает старый ключ. Учебное пополнение меняет состояние окна без вызова
платёжного провайдера. Подтверждённый выход завершает предпросмотр, а не серверную
сессию.

Диагностика скачивает сводку разрешённых полей без промптов, ответов, credentials
или состояния Desktop. Ошибки, отсутствие бэкенда и предупреждения о расчётах
остаются видимыми, даже если интерфейс не повторяет пометку демо.

## Отдельное окно из лаунчера

1. В корне репозитория запустить `bun run web:dev`.
2. В другом терминале запустить `bun run app:dev`.
3. Выбрать «На сервере» → «Открыть демо Hosted».

Development-окно `hosted-preview` использует фиксированный loopback-адрес и
InPrivate/incognito без разрешений Desktop. Произвольная навигация и новые окна
заблокированы. Повторное открытие фокусирует существующее окно; его закрытие не
останавливает локальный API. В release-сборках кнопка скрыта, команда отклоняется.
Браузерные тесты с mock не подтверждают работу настоящего WebView2.

## Структура

- `src/features/` — страницы, модели представления и их логика.
- `src/components/` — общий UI и копирование с ручным резервным способом.
- `src/i18n/` — реестр языков, загрузка и словари.
- `src/preview/` — development-вход, учебные данные и операции в памяти.
- `tests/unit/` — представление, арифметика, неизвестные значения и границы данных.
- `tests/e2e/` — маршруты, взаимодействия, темы, локализация и адаптивная компоновка.

## Проверки

Из `hosted/web/` выполнить `bun run test`, `bun run build` и `bun run test:e2e`.
Установка Chromium, требования и точечные команды описаны в
[проверках web preview](../../docs/CONTRIBUTING.md#web-preview). CI проверяет пакет
отдельно. Production-preview использует порт 4174, браузерные тесты — 1442,
а development-сервер — 1441.

Будущие серверные контракты находятся в [архитектуре Hosted](../../docs/hosted/HOSTED_RELAY_ARCHITECTURE.md)
и [плане web-интерфейса](../../docs/hosted/HOSTED_RELAY_WEB_DESIGN.md). Успешные
UI-проверки не закрывают приёмку бэкенда, авторизации, биллинга или установленного
WebView.
